## D2.54：dpqr 失败族首批——MN3/MN4/MN5 支持域探测修复 + ZABB/ZIBB bd 契约

- **六个族的 dpqr fail / rsdev skip 全是探测网格溢出支持域**，不是实现缺陷（但 ZABB/ZIBB 的族元数据确是真缺陷，见下）。

- **MN3/MN4/MN5（1..k 分类族）**：R 的 dMN3 对 x∉[1,3] 直接 `stop()`（"x must be 1, 2 or 3"），通用离散候选（0..7、1..8、连续）都在域外 → R 侧无法求值，报出的 failure 是探测缺陷；拟合样本也按 0..7 抽 → R fit 报 "response variable out of range"。修法：scanner 加 `_SUPPORT_BOUNDS` 表，这三族用**支持域本身**当探测网格，**平铺到 n 长度**（两侧都验证过：不平铺时我们广播报错、R 回收成 NA 报 "missing value where TRUE/FALSE needed"），`ok` 判据改为"每个支持点密度有限为正"（MN3 支持仅 3 点，够不到通用 n-1 阈值）。
- **ZABB/ZIBB（0..bd beta-binomial）**：族对象没声明 `bd` 为固定参数 → 扫描器不传 bd，R 落回默认 bd=1 → "x must be <= the binomial denominator 1"；拟合样本 0..7 也让 R 报 "y values must be 0 <= y <= 1"。且内核拒绝探测携带的 float/向量 bd（`dZABB` 的 `_check_bd` 要求单个静态 int——它按 bd 建内部网格）。修法：两族加 `fixed_parameters=("bd",)`（BI 已有的形状），d/p/q 用 `_static_bd` 把**常量向量折叠成静态 int**（非常量拒绝），拟合走 cbind(y, fail)。
- **连带回归（已修）**：`fixed_parameters` 生效后 deriv 闸把 `bd=10` 传给分数函数，而 AD 分数把 bd 烘焙在闭包里、不接受该关键字 → ZABB/ZIBB deriv pass→fail。修法：`gate_derivatives` 加 `call()` 回退（带 extra 调用失败则不带 extra 重试），与 `_python_dpqr` 已有的回退模式一致。
- **实测**：MN3 dpqr/rsdev 102.909 vs R 102.909、MN4 127.737 vs 127.738、MN5 153.062 vs 153.062；ZABB 208.312 vs 208.313、ZIBB 209.81 vs 209.811；六族 deriv/dpqr/rsdev 全 pass。
- 新测试 `tests/test_support_bounded_dpqr.py`（8 例）：校准网格在支持域内、拟合样本在域内且整数、d/p/q 对活 R 逐值（含 R ifelse 回落：`[1,k]` 内非 1..k-1 的值携带参考类质量）、bd 为固定参数、常量向量 bd 接受/非常量拒绝、带 bd 的 d/p 对活 R。
- **教训**：探测网格必须落在族自己的支持域内（D2.28 的又一形态）；声明 `fixed_parameters` 会改变探测载荷形状，必须同步检查 deriv 闸的调用约定。

## D2.55：BE* 四族 dpqr/rsdev 修复——[0,1] 支撑族的边界路由与探测网格

- **三个叠加缺陷**：①密度边界路由用 `y<=0 / y>=1` 而非精确相等，R 是精确相等分流并在域外清零（且每族规则不同：BEINF 两端原子、BEINF0 只 0 原子且 x>=1 为 0、BEINF1 只 1 原子且 x<=0 为 0、BEZI x>=1 为 0、BEOI x<=0 为 0）——旧路由让 x>1 落进原子（dBEINF(2)=tau/(1+nu+tau)、dBEZI(2.41)=3121.8、dBEINF0(1)=1.7e+11）；②通用探测网格 0..7 溢出 [0,1] 且我们宽松的密度在域外返回有限值，每个域外点都被计为"好点"；③`_fit_data` 给所有 Mixed 族注 30% 的 0，但 BEINF1/BEOI 支撑是 (0,1] 无 0 原子 → R fit 报 "response variable out of range"。
- **两套平行实现都要修**：distributions_b4.py 的 `_be*_log_pdf`（AD 拟合路径）与 dpqr_functions.py 的 `_beinf_logpdf`（fam.d 路径，之前用 eps 阈值）——只修前者时 dpqr 闸因新网格只在 [0,1] 内比较而"看起来"通过，测试在域外才暴露。这是 D2.41「平行实现收成同一实现」教训的又一实例。
- scanner 加 `_UNIT_SUPPORT`（五族固定 `linspace(0,1,n)`，不走评分——内部网格得分更高会静默丢掉原子）与 `_UNIT_ATOMS`（原子位置表，驱动拟合样本注入）。
- 结果：BEINF/BEINF1/BEOI/BEZI 的 dpqr fail→pass、rsdev skip→pass（8 闸）；BEINF0 保持 pass。rsdev 数字：BEINF 50.8072、BEINF0 61.7269、BEINF1 63.3348、BEZI 63.6041、BEOI 53.7977，全部与 R 逐位一致。
- 新测试 `tests/test_unit_interval_inflated.py`（5 例）。

## D2.57：GU/RG 的 p/q 互换、ST3C 的 tau 下限、数值 CDF 的积分窗口——dpqr 失败清零

- **GU/RG 的 CDF 与分位数互换**：密度本来正确（dGU 最小 Gumbel、dRG 最大 Gumbel），但 pGU 用了最大 Gumbel 公式、pRG 用了最小，q 随之；pRG 还把 z 写成 (mu-q)/sigma。活 R 数值：pGU(0.3,0.5,0.5)=0.4884552=1-exp(-exp(z))、pRG=0.2249618=exp(-exp(-z))。qGU=mu+sigma*log(-log(1-p))、qRG=mu-sigma*log(-log(p))（R 的 qRG 在 p==0 给 0 是 quirk，我们给 -Inf 并登记）。
- **ST3C 的 tau 下限**：CDF/q 把 tau 钳在 1.0，但 R 支持 df<1（pST3C(-1,nu=.5,tau=.5)=0.6058544583）。去掉下限后四个参数角与 R 一致到 1e-11。
- **共享数值 CDF 的积分窗口**（GT/SHASH 共用）：有限窗口 mu±(8*max(|σ|,1)+8) 再归一化，对 GT 重尾（nu=tau=0.5 时密度按 |z|^-1 衰减）丢掉 5.34% 质量。改为从 -Inf 积分（同 R 的 pGT）；SHASH 实测不受影响。
- **扫描器口径**：R 侧自身数值失败（GT 的 qGT: "roundoff error is detected in the extrapolation table"）记为"无 R 参照"而非族缺陷——"R 答错"与"R 答不出"是两回事。
- 结果：GU/RG/GT/ST3C dpqr fail→pass，**dpqr 闸 146 族 0 fail**（111 pass / 35 skip）。新测试 `tests/test_gumbel_st3c_numeric_cdf.py`（11 例）。

## D2.58：R 桥的 warning 口径 + BCTO tau 容忍 + BB 缺口登记

- **R 桥把 fit 期间的任何 warning 当错误**（r_parity_batch.R 的 `tryCatch(warning=...)`）——而 R 对"RS 未收敛"正是发 warning（BCTO 撞周期预算即触发），于是该族 rsdev 永远是 skip。改为 `withCallingHandlers` 记录告警并继续，结果里带 `warnings` 字段；BCTO 的 rsdev 因此可测（R 未收敛 → warn，与 ZIPIG/ZINBI/PE2 同类）。
- **BCTO 的 tau deriv**：BCTO 是 BCTo 的重命名克隆（R 安装版 6.1.1 没有 BCTO），其 tau 分数转录自 R 的 BCT dldt（0.01 前向差），而闸的中央差看真导数 → 2.689e-03。按 BCT 已有的登记（1e-2 + note）为 BCTO 补同款条目，并记录实测证据。
- **BB 缺口（未修，记录）**：BB 的 `parameters=("mu","sigma","bd")` 把固定参数 bd 同时放进参数列表，扫描器既为 bd 造网格又额外传 bd → `dBB() got multiple values`。改成 BI 的形状（bd 只在 fixed）会让 AD 路径缺 bd（`_bb_log_pdf(y,mu,sigma,bd)` 无默认）。因 BB 的 rsdev 已 pass、且修复会牵动拟合路径，本轮不动；BB 的 deriv/dpqr 仍是 skip（未测量，非失败）。修复方向：`_bb_log_pdf` 给 bd 默认值 + `fixed_parameter_defaults={"bd": 10.0}`，并让拟合把数据里的 bd 透传到 AD 密度（同 NET 的固定参数模式）。
- **NET 的两项 skip 是正当的**：NET 是自有族（R 无对应），deriv 的 skip 源于固定参数 nu/tau 被当成自由参数造网格导致密度无效——同样留待统一处理固定参数网格。

## D2.59：初值三缺陷的第二/第三簇——LNO/LOGNO/LOGNO2、SEP/SN2/EGB2、BNB/ZABNB/ZIBNB

**根因（与 D2.53 SI 完全同款）**：`_initial_sigma` 对逐点 mu 目标求残差尺度，残差恒 0 → sigma 起在 eps 地板。实测 11 个族全部 sigma0=2.2e-16。R 的初值式全部是**固定尺度**，与 mu 目标无关。

- **簇 1（LNO/LOGNO/LOGNO2）**：R 的 mu.initial=(log(y)+mean(log(y)))/2、sigma.initial=sd(log(y))（n-1）。我们逐点 log(y) + 残差尺度 → sigma=eps。LNO 因此 1e13、LOGNO2 也 eps 起步。
- **簇 2（SEP/SEP1/SEP2/SN2/EGB2）**：R 的 mu.initial=(y+mean(y))/2；sigma=sd(y)/4（SEP 三兄弟）/sd(y)（SN2）/0.1（EGB2）；nu=0.1、tau=1.6（SEP 三兄弟）。我们 mu=y、sigma=eps、nu=1.0、tau=1.0。
- **簇 3（BNB/ZABNB/ZIBNB）**：R 的 mu=(y+mean(y))/2、sigma=max((var(y)-mean(y))/mean(y)^2, 0.1)（n-1 var）、nu=0.1、tau=零比例（ZABNB）/0.1（ZIBNB）。我们 sigma=0.0。

**修后结果（全族流扫描前单族验证）**：
- LNO fail→pass（137.87 vs R 137.87）；LOGNO/LOGNO2 保持 pass
- SEP2/SN2/EGB2 fail→warn（R 未收敛，我们 132.017/132.139/131.936）
- BNB fail→warn（py 198.741 vs R 198.699）
- ZABNB fail 23.7%→4.3%、ZIBNB fail 27.6%→10.9%（仍差，见下）

1. **初值全缺失**：registry key 是 JSUO，但族对象 .name 是 "JSUo"（distributions_b14 的 build_ad_family(name="JSUo")，o_alias_compat 的 _clone 也传 "JSUo"）——_fitting_init.py 无任何条目，四参数全走 generic fallback（mu target=y、sigma=残差 eps 地板、nu=1.0、tau=1.0）。基线拟合 mu=[1.9e7, 0.80]、sigma=e^15.06 完全发散，deviance 1613.89 vs R 146.78（rel 10 倍）。活 R dump：mu.initial=(y+mean(y))/2、sigma.initial=0.1、nu.initial=0、tau.initial=0.5；links mu=identity/sigma=log/nu=identity/tau=log（与我们一致）。

**修法**：_fitting_init.py 补四个 JSUo 分支（注意 .name 大小写）；distributions_b14.py 加 _JSUO_SCORES/_JSUO_HESSIANS（R 闭式转录，SHASHo2 D2.40 同款 override 模式），JSUo() 接 score_overrides/hessian_overrides。_clone 会复制 score_functions/hessian_functions，别名 JSUO 自动继承。

**结果**：20 周期 146.8435 vs R 146.7781（rel 4.5e-4，闸 pass）；系数 mu=[1.299, 0.083] vs R [1.306, 0.080]、sigma=0.550 vs 0.572、nu=-0.820 vs -0.814、tau=0.633 vs 0.656。双方都未收敛（仍在降），轨迹形状一致（R：168.85→146.78 单调）。deriv 闸仍 pass（override 的 score 正是被检对象——转录正确性的守门人）。新测试 omnilss/tests/test_jsuo_fit_parity.py（8 例：初值对活 R 求值、score 对 R 的 dldm/dldd/dldv/dldt、hessian=-score² 形式、score 与密度中心差自洽、拟合 parity、不发散）。

**遗留线索**：JSU（非 o）与 SHASH/SHASHO 的 R d2ld*2 槽更复杂（非简单 -score²），未查是否同型缺陷——SHASH/SHASHO 的 1-2e-3 残留差距是候选。ZABNB/ZIBNB 的诊断结论（R 自身振荡 + sigma 撞 eps 地板）已登记在上一节。

## D2.61：SEP1 从"无法拟合"到 parity pass——R 闭式 score/hessian override

**问题**：SEP1 的 rsdev 闸在**每个样本**上报 "python raised NotImplementedError: Differentiation rule for 'igamma_grad_a' not implemented"——族完全无法拟合。deriv 闸却 pass，这是关键线索：SEP1 密度走 gammainc(1/tau, s)，JAX 能求一阶导（d/da 由 igamma_grad_a 承担），但二阶导再进 igamma_grad_a 没有规则 → **拟合需要的 Hessian 建不出来**。与 build_ad_family docstring 里 BCT/BCPE 的既有记录完全同型。

**修法**（D2.40 SHASHo2 / D2.60 JSUO 同款）：转写活 R 的 SEP1() 槽位——
- dldm/dldd/dldv：闭式（由 lpdf、lcdf、pgamma 组合）
- dldt：解析 dldf + CDF 部分的双侧差分（t1=tau+2e-5、t2=tau-2e-5）——R 自己也对 pgamma(s,1/tau) 求不了 tau 导数，parity 就是用 R 的差分而不是更好的导数
- d2ldX2 = -dldX²（GN 形式）
接进 SEP1() 的 score_overrides/hessian_overrides，整族脱离 AD 路径。b15 模块级补 gammainc 导入（原来只在密度函数内局部导入）。

**结果**：全族流样本 20 周期 **124.842834 vs R 124.842999（rel 1.3e-6）**，系数 mu=[2.11014, 0.08969] vs R [2.10954, 0.09048]、sigma=0.403384 vs 0.403319、nu=-0.235024 vs -0.236274、tau=2.743305 vs 2.743568；双方 converged=False（R 报 "Algorithm RS has not yet converged"）。deriv 闸 pass。

**deriv 闸的 tau 容差登记**（1e-2 + note）：R 的 dldt 把 CDF 项写成 log(1+pgamma(s,1/tau))，**漏了真实 lcdf 的 sign(w)**；实测 R 自己的 dldt 对 R 自己 dSEP1 的中心差（h=1e-6）在 5 个探针点上 rel = 8.1e-11/1.1e-10/4.4e-11/**5.7e-1**/1.1e-10——第四个点 (y=4,mu=2,sigma=0.5,nu=-1,tau=1.5) 深负尾 R 自己差 57%。我们照抄 R 的公式，闸在标定网格上看到 1.489e-3。修导数会离 R 更远（D2.15）。（顺带记录：dldv = exp(lpdf-lcdf)*(w/nu) 在 nu 恰为 0 且 w=0 时是 0/0=NaN，R 与我们同为 NaN；拟合从 nu=0.1 起步不会触到。）

**新测试** omnilss/tests/test_sep1_fit_parity.py（6 例）：不再抛 NotImplementedError、hessian=-score²、四个 score 对 R 的 dldm/dldd/dldv/dldt、mu/sigma/nu 与密度中心差自洽、拟合 parity、系数贴合 R。

## D2.64：ZABNB/ZIBNB——R 的报告 deviance 是数值垃圾（闸加"R 参考无效"类别）

**表面症状**：rsdev ZABNB 211.719 vs R 202.905、ZIBNB 221.177 vs R 199.444——我们更高，按惯例是缺陷方向。

**真相（sigma 扫描铁证）**：用 R **自己的** dZABNB/dZIBNB 在 **R 自己拟合出的** mu/nu/tau 上扫 sigma：

| sigma | 1e-4 | 1e-6 | 1e-8 | 1e-10 | 1e-12 | 1e-15 | eps |
|---|---|---|---|---|---|---|---|
| ZABNB | 214.8326 | 214.8255 | 214.8254 | 214.8254 | 214.8279 | 213.3046 | 204.9114 |
| ZIBNB | 221.3789 | 221.3749 | 221.3748 | 221.3748 | 221.3743 | 221.0975 | 219.8483 |

似然在 1e-6..1e-10 平坦，逼近双精度地板时**崩塌**（dBNB 的 m=1/sigma+1 与 n=mu*nu/sigma 都到 1e15，log 密度是它们的差 → 灾难性抵消）。R 的优化把 sigma 精确推到 **2.220446e-16**（exp(-36.04)）、converged=FALSE、逐周期 deviance 在 189~214 间振荡——所以它报告的 202.905/199.444 **不是任何 sigma 下的似然值**，是未收敛迭代的中途陈旧快照（R 自己的 -2*logLik(m) 与 G.deviance 相同也只是复用同一存储值）。

我们的拟合停在 211.7189/221.1768，**低于 R 的数值有效值 214.83/221.37**。我们自己的密度在 sigma=eps 处返回 NaN（同样的抵消），因此拟合不跟 R 下地板。

**实施**（两件）：
1. ZABNB/ZIBNB 接 R 的 hurdle 修正 score + d2ldX2（ZABNB 的 d2ldt2 = **-1/(tau(1-tau))** 不是 -score²；ZIBNB 的 dldt 分段）。deriv 闸 pass，证明转写是自家密度的真导数。注意这两项**不改变**本样本的拟合结果（瓶颈是 sigma 撞钳位，不是权重形状），属于"轨迹在别处有意义时也对"的正确性投资。
2. scanner 新增 _RSDEV_R_REFERENCE_INVALID 类别（与 _RSDEV_R_STOPPED_EARLY 不同：那里 R 在真实但更差的点；这里 R 的报告值在任何点都不成立）。闸改用 R 密度在 sigma=1e-10 的值作参考，且**要求我们低于它**才给 warn，并复核记录数字防漂移。

**新测试** omnilss/tests/test_zabnb_zibnb_r_reference.py（10 例）：R 的 sigma 落在双精度地板、R 似然在 1e-6..1e-10 平坦且在地板崩塌、报告值≠地板处值、我们低于 R 有效值、四个 hurdle score 与 d2ldt2 对活 R。

**方法论沉淀**：**"我们更高"不必然是缺陷——先扫 R 的似然在它自己参数上的稳定性**。若 R 的落点在浮点地板，报告值可能整体失真，此时该发明的是"参考无效"类别而不是去追那个数。

## D2.71：ZABI/ZIBI 的 bd 支持——"ZIBI 密度不一致"其实是非法样本（探针从 skip 变实测）

**起点**：D2.70 把 ZIBI 明确搁置，理由是"我们的密度 64.668 vs R 78.270，前若干观测逐位一致、从第 3 个起 R 重复输出同一个值"。线索指向 R 侧参数回收，但没有定论。

**根因（两条，都不在密度公式里）**：
1. **拟合样本非法**。ZIBI 由通用工厂建在**无 bd 的二项**上（等价 Bernoulli），支撑是 {0,1}；而扫描器的拟合样本按族的响应范围抽整数，通用离散网格是 0..7。我们自己的密度对 y=5 仍给有限值（y*log(mu)+(1-y)*log(1-mu)），R 的 dZIBI 直接拒绝。64.668 vs 78.270 是"我们给非法 y 打分"的产物。
2. **R 的族本身是 bd 参数化的**：dZABI/dZIBI(x, bd, mu, sigma)，bd 与 dBI 一样是固定参数。我们的族根本无法表达 bd>1。

**实现**：把 ZABI/ZIBI 从通用工厂换成专用构建器 _make_binomial_zero_variant：
- 布局照 R：parameters=("mu","nu","bd") + fixed_parameters=("bd",) + fixed_parameter_defaults={"bd":1.0}（BB 范式：bd 既进 AD 闭包又由拟合从数据解析）。
- d/p/q 完全照 R 公式（ZIBI 零点 log(nu+(1-nu)f0)；ZABI 零点 log(nu)、非零 (1-nu)f0/(1-f0) 条件化）；p/q 里 ZABI 的 hurdle 反演用 R 自己的 F(0)*(1-pnew)+pnew，epsilon 1e-10。
- **score 照 R 的转写**，不是 AD：d2ldm2=-dldm^2、d2ldd2=-dldd^2，ZABI 的零点用精确 -1/(nu(1-nu))。实测与 R 族对象函数逐点一致（dldm 3e-14、d2ldm2 4e-13、dldd 3e-15、d2ldd2 0）。
- 初值照 R：mu.initial=rep(0.5)（logit 尺度 0，**常数**，不是数据驱动）、sigma.initial=rep(0.3)（D2.26 曾把这两族按文件名归到 0.1 分支，实测活 R 的 family 对象是 0.3）。
- distributions_zero_alias_compat._clone 补 fixed_parameter_defaults 透传——注册表走 clone 壳，默认值原本在那里丢失，导致 "requires fixed parameter bd in data"。

**第二个真缺陷（探针侧）**：_q 的首参叫 prob，而探针按名调用 q(p=...) → TypeError → 回落位置调用 → bd=10 被喂给 mu，两族都报 q: max rel 1.000e+00。改名 p 后 dpqr 全 pass。

**R 侧的第三个缺陷（这次是 R 错，两个族都有）**：R 的 dZIBI **不是逐元素的**。零分支 log(sigma+(1-sigma)*dBI(0,bd,mu))，而 dBI=dbinom(x,size,prob)；dbinom 在**标量 x + 向量 prob** 下返回**标量**（不按 prob 回收）。实测：dBI(0,bd=1,mu=c(0.1,0.2,0.3)) → 0.9（长度 1），dBI(c(0,0,0),...) → 0.9 0.8 0.7；于是 dZIBI(c(0,0,0),bd=1,mu=c(0.1,0.2,0.3),sigma=0.3,log=TRUE) → -0.07257069 x3（全是第 1 行的 f0）。这就是 D2.70 看到的"R 重复输出同一个值"。

**同一缺陷的第二处（ZABI）**：dZABI 的**非零分支**也有同样的塌缩——hurdle 修正项 -log(1-dBI(0, bd[x!=0], mu[x!=0])) 里 dBI 的首参仍是标量 0，所以所有正观测都用**正子集第 1 行**的修正。ZABI 的零点分支是 log(sigma)（没有 dBI），所以这个缺陷在 bd=1、mu 近似常数的样本上几乎看不出来——D2.70 的退化 Bernoulli 样本让 ZABI 的 rsdev 一直 pass。换成 bd=10、mu 在 0.38~0.50 变化后：第 45 行（y=2）用的是 dBI(0,bd,mu)=0.018728 而不是它自己的 0.008355，R 报 217.122618，逐元素重算 217.372671，我们 217.358660。

**登记**：新增闸类别 _RSDEV_R_DENSITY_RECYCLED（与 _RSDEV_R_REFERENCE_INVALID 区分：那里的参数在浮点地板、密度是对的；这里参数正常、**密度错了**）。要求：R 的报告值、R 自身系数处逐元素重算的参考值、我们的值三者都与登记数字吻合，且**我们低于参考值**，才给 warn。两个族都在内（全族流 n=8、bd=10）：ZIBI R 报 211.998201 / 逐元素 211.785367 / 我们 211.777840；ZABI R 报 217.122618 / 逐元素 217.372671 / 我们 217.358660。注意方向相反：ZIBI 的回收**抬高** R 的数，ZABI 的回收**压低** R 的数。

**新测试** omnilss/tests/test_binomial_zero_variants_bd.py（23 例）：参数布局与 bd 默认值、d/p（bd=7 的 R 字面量，1e-13）、q（整数精确）、越界质量为 0、bd 真的改变密度、三个 score 槽与 R 转写一致、ZABI 零点的精确 hessian、合法样本的拟合自洽（deviance == -2Σlog）、以及 **R 回收缺陷的活证**（调用 dZIBI 三行同值 + dBI 标量/向量对比，并断言我们的密度给三个不同值）。同时更新 test_zero_variant_probes.py（ZIBI 进映射表、探针网格到 bd）、test_zero_variant_nu_initial.py（0.3 分支 + 修掉 D2.59 遗留的 ZABNB/ZIBNB 陈旧记录）、test_basic_batch10.py（parameters 含 bd、pdf 传 bd）。

**方法论**：
- "两个数都对不上"时先把**样本合法性**查一遍：密度公式再对，喂进非法响应也会得出一个"看起来像差异"的数。
- 单测 R 的底层函数（dBI(0, bd, mu_vector)）比对比整族 deviance 快得多，也更能定性"谁错"。

- ZABI/ZIBI 的 rsdev 都停在 rel≈1e-3 边缘：改成合法 bd=10 样本后我们比 R 的*逐元素正确*参考还低，但我们的 RS 在本样本上落在 nu=0.165 的内部驻点（真实 MLE 在 nu=0 边界，差 0.005）。这是"局部驻点"课题，与 GP/PARETO2 同族，不属于本任务。

## D2.72：NET 的 deriv/dpqr 闸从未运行——探针常量表是空的，且自动密度不接受关键字参数

**症状**：NET 是唯一同时 deriv skip + dpqr skip 的族。两个 skip 的 detail 都不'是"R 没有对应函数"——R 明明导出 dNET/pNET/qNET/rNET。

**根因（两个叠在一起）**：
1. `_PROBE_FIXED_CONSTANTS` **从写下来就是空的 dict**。它的注释说 NET 的 nu/tau 是非估计量（R 的 parameters = list(mu=T, sigma=T, nu=F, tau=F)），nu.initial=1.5 / tau.initial=2，dNET 拒绝 nu<=0——但表里没有 NET。于是 nu/tau 按 identity 链接走通用网格（-2.0 .. 3.0），R 在第一站就 stop("nu must be positive")，闸记成 "no d/p/q counterpart in R"。
2. 补上常量后 dpqr 变成 "d: no Python function"、deriv 仍是 "no support grid yields a finite density"：`build_ad_family` 生成的密度是 `def _d_auto(*args, log=False)`——**没有命名参数**，`nu=` 关键字直接 TypeError；而闸的位置回落只拼了网格参数（mu/sigma），把常量漏掉了。

**修法**：
- `_PROBE_FIXED_CONSTANTS = {"NET": {"nu": 1.5, "tau": 2.0}}`（R 自己的非估计默认值）。
- 新增 `_our_call_args(fam, first, params_values, bd, consts)`：按**族自己的 parameters 顺序**拼位置参数（网格跳过常量与 bd），并把不在 parameters 里的固定参数**追加到末尾**——DBI 就是这种情况（parameters=(mu,sigma)，_dbi_dispatch(x, mu, sigma, bd)）。calibrate 的 score()、_python_dpqr 的位置回落、都改走它。
- `gate_derivatives` 的 params 列表排除探针常量（原来只排除 bd），否则 base_map[pname] 直接 KeyError。

**结果**：NET 三闸全 pass（deriv 145→**146 pass / 0 skip**）。实测 d/p/q 与活 R 在标准探针网格上 d/p **maxdiff 0**、q 9e-16。

## D2.74：分位数残差覆盖 5→140 族——通用 rqres 走族自己的 CDF

**问题**：`_build_rqres_callable` 只给 PO/BI/GEOM/NBI/ZIP 五个族建残差核，其余 141 族返回 None，
模型退回 `_compute_residuals` 的原始 `y-mu`（或 Pearson 式 `(y-mu)/sqrt(mu)`）。这两种残差**不能跨族
比较**，而分位数残差正是 GAMLSS 诊断的基础（虫图、百分位曲线）：正确模型下若不近似 N(0,1)，诊断没有意义。

`u=(F(y-1)+F(y))/2`（R 的 rqres 是 `runif(F(y-1),F(y))`，确定性实现无法复刻随机性；中点与既有 5 个手写核
一致，且原子处 F(低于支撑)=0 使中点落在原子质量下半，与 R 的抽样期望相同）。参数按族自己的 parameters 顺序
拼位置参数、tuple 外的固定参数追加末尾（D2.72 在探针侧踩过的同一个坑）。4 个 CDF 占位族
（DPO1/GENERALISEDPOISSON/IGA/LOGSHASHO）仍返回 None。

**关键修复：所有调用点都要传全部参数**。原来三处只传 y/mu/sigma，ZIBI 的 CDF 因此拿到 bd=1 默认值，
y>1 的 p 全饱和到 1，60 个残差全变成 `qnorm(1-eps)=8.126`。改为 `{**parameter_values,
**fixed_parameter_values}`（与 deviance 同一份字典），`gamlss_ml` / `gamlss` / `rs_fit` 三处同步。

**验证**：通用路径与 5 个手写核逐点一致（6.1e-16）；NO/GA 在正确模型下 KS vs N(0,1) p=0.90/0.82；
全族拟合扫（146 族 × 40 观测 × RS 10 周期）**140 族残差全有限**、4 族无 CDF 跳过。

**新测试** `omnilss/tests/test_generic_rqres.py`（11 例）：覆盖率、占位族仍 None、复现手写核、KS 检验、
拟合残差有限、ZIBI(bd=10) 回归（残差不能全等 8.1259）。

## D2.76：Bessel 回调在 vmap 下逐元素往返 + tofySICHEL 扫满 10 万项

**两个性能缺陷（都在 Sichel 家族的 score 路径上）**：
1. `log_bessel_kv` / `log_bessel_iv` 用 `jax.pure_callback(..., vmap_method="sequential")`，vmap 到 n 个
   观测就发 n 次宿主回调；Sichel 的 score 每个元素要 4 次 Bessel，于是 n=48 的一次 score 要 192 次往返。
   改成 `vmap_method="expand_dims"`（scipy 的 `kve`/`ive` 本来就广播），整批合成 1 次调用。
2. `tofySICHEL` 的 `lax.scan` 对每个观测扫满 `SICHEL_DENSITY_MAX_COUNT`=100000，而 scan 唯一的作用是
   接住 `j == floor(y)`。按调用里最大的 y 截断（traced 值回落全预算）。

**实测**（n=48 的一次 score 调用，第二次调用即编译后）：1.01 s → 0.45 s（批量化）→ **0.14 s**（加截断），
合计约 **7×**。12 观测、1 个外周期的 ZASICHEL 拟合：216 s → **172 s**。

**为什么拟合只快了 1.26×**：一次 score 0.14 s 里，绝大部分是 `pure_callback` 的**宿主往返地板**（4 次
× ~35 ms），而一次拟合要上千次 score。所以拟合时间 = 调用次数 × 单次地板。**真正要解决得把
`log_bessel_kv` 变成 JAX 原生实现**（scipy 的 kve 在 JAX 里没有；需要渐近展开 + 递推 + 自定义 JVP），
那是独立一轮的工作量。本轮不做，也不宣称"修好了"。

**值中性验证**：`log_bessel_kv`/`log_bessel_iv` 在 vmap 下与 scipy 逐元素一致（1e-13，5 个 nu 值）；
nu 为数组时也一致；`tofySICHEL` 批量结果与单点结果一致（含 y=40 的大计数）。Sichel 三族的 deriv/dpqr
闸不变，SI/GIG/PIG/ZAIG（同样用 Bessel）三闸全 pass。

**新测试** `omnilss/tests/test_bessel_vmap_batching.py`（13 例）。

## D2.79：GENERALISEDPOISSON 的密度不符合自己的文档（E[Y]=mu 不成立），且没有 CDF

**证据链**：族文档写「GP(mu, sigma) with E[Y] = mu」，而 `_gp_log_pdf` 实现的是**未平移**的 GP1 形式
（λ=μ/(1+σ), p(y)=λ(λ+σy)^{y-1}e^{-(λ+σy)}/y!）。这个分布本身合法（PMF 求和精确为 1），但**不是均值参数化**：
mu=2, σ=0.5 时均值是 **2.667**；mu=5, σ=0.2 时是 **5.208**。同一网格上 R 的 GPO 给出 2.000 / 5.000。
而且它的 `p/q` 是占位（`pGENERALISEDPOISSON` 返回 NaN），R 里也没有这个函数——三闸一直 skip。

**改动**：`GeneralisedPoisson()` 改为共享 GPO 的内核（d/p/q/r + sigma 用 log 链接），删掉那段死掉的未平移密度；
compat 壳 `GENERALISEDPOISSON` 本来就从它复制，于是自动获得真实 CDF。扫描器加别名
`"GENERALISEDPOISSON": "GPO"`，并在 `_fitting_init` 的两处按名分支里补上它（mu 初值 `(y+mean(y))/2` 走 log、
`sigma.initial=0.1`）——不补的话 rsdev 停在 231.063 vs R 218.645（rel 5.7e-02），纯粹因为初值走了通用残差尺度。

**⚠ 行为变更（必须在 release note 里写清）**：GENERALISEDPOISSON 的**密度参数化变了**（现在是均值参数化，
与 R GPO 一致），**sigma 链接从 identity（带 clip）变成 log**（sigma 不再允许负值）。用这个族拟合过的历史结果
不可直接比较。

**结果**：GENERALISEDPOISSON deriv/dpqr/rsdev **全 pass**（原 3 skip）；残差覆盖 141→142；`has_dqr` 143→144/146；
占位 CDF 族剩 **DPO1 / LOGSHASHO**（R 里既没有这两个函数，也没有可借用的同名内核）。

**方法论**：判断「两个同名族是不是同一个分布」不能只看名字或 PMF 求和——**求和为 1 只说明它是合法分布**，
要看文档承诺的矩（这里是 E[Y]=mu）。这也是 IGA（D2.77）之后的第二例：别名族丢了内核。

## D2.80：DPO1 根本不是密度——PMF 求和为 +inf，零点还有无穷尖峰

**证据**：旧实现把 `0.5*log(2*pi*sigma*y)` 当作"近似归一化常数"加进去，又在同一个表达式里减掉同一项，
结果只剩 `log f(y) = (y log mu - mu - log y!)/sigma`——一个**缩放 Poisson**：只有 sigma=1 时才归一，
而且 y=0 处因为减去的 log(0) 变成 **+inf 尖峰**。实测（mu=3）：PMF 求和 **+inf**（sigma=1/0.5/2 全部），
均值 3.000 / **0.456** / **10.171**；同一网格上 R 已验证的 DPO 求和 1.000、均值 3.013 / 2.999。
族还缺 CDF，且 `type` 是 Continuous（双 Poisson 是离散）。

**改动**：`DPO1()` 改为共享 DPO 内核（密度/CDF/分位数/采样 + Discrete 类型 + log 链接），删掉那段伪密度；
扫描器加别名 `"DPO1": "DPO"`；`_fitting_init` 的三处 DPO 分支补上 DPO1（mu 初值 `(y+mean(y))/2`、
`sigma.initial=1`）。

**结果**：DPO1 三闸 **3 skip → 3 pass**；残差覆盖 142→143；`has_dqr` 144→145/146（只剩 LOGSHASHO）；
**能力表里 placeholder 计数归 0**。

**测试**：新增 `test_dpo1_is_a_density.py`（9 例：PMF 有限且归一、均值近似 mu、Discrete + 真 CDF、与 DPO 内核一致、
拟合残差有限）。均值用 rel=1e-2 而不是 1e-6——双 Poisson 的归一化常数在 gamlss 里本就是**近似**，R 自己的 dDPO
在 sigma=0.5 时均值也偏 0.4%（3.0129），这正好是 DPO1 现在继承的数字。

**测试维护**：`test_ad_families_without_explicit_dpqr_are_marked_placeholder` 的样本族已清零（D2.73 用 DPO1/IGA、
D2.79 剩 DPO1、D2.80 归零），改成断言"placeholder 集合为空 + 检测器仍能识别占位函数"；
`test_method_route_capability_report_supports_service_admission` 里针对 placeholder 路由的断言改为
"DPO1 不支持的 RS_JAX 被拒（unsupported_route）"。

**三连击的规律（IGA→GENERALISEDPOISSON→DPO1）**：这批"兼容别名/批次生成"的族**丢了 d/p/q 内核**，
而它们的名字在 gamlss.dist 里都不存在，于是三闸安静地 skip 了很多轮。判据不是"名字像不像"，而是
**文档承诺的矩**（E[Y]=mu）与**PMF 是否归一**。

## D2.81：LOGSHASHO 的密度与 CDF 描述的是两个不同的分布（R 自己的源码就自相矛盾）

**证据**：vendored `gamlss.dist/R/LOGSHASHo.R` 里两半做的是不同的事——
`dLOGSHASHo` 用 `z=(x-mu)/sigma`（对 **x**，不是 log x）再 `ft[x<=0]<-0`，本质是**截断的 SHASH 且不重新归一**；
而 `pLOGSHASHo` 写的是 `cdf <- pSHASHo(log(q), ...)`。两者不可能同时对，而且密度那一半不是密度：
mu=0,sigma=1,nu=0,tau=1 时它在 (0,∞) 上只积到 **0.500**；mu=-1 时 **0.0023**。
（注意：装好的 gamlss.dist **并未导出** dLOGSHASHo/pLOGSHASHo，只有源码，所以从来没有 R 对照。）

**判断**：p、q、r 三者都与"对数变换"读法一致，只有 d 不一致 → 采用**对数变换**语义（Y=exp(X), X~SHASHo）。

**改动**：
- `d = f_SHASHo(log y)/y`（即 d/dy pLOGSHASHo）；
- `p = pSHASHo(log y)`（照 R 的 pLOGSHASHo，R 的 SHASHo 本身已验证）；`q = exp(qSHASHo)`；`r = exp(rSHASHo)`；
- 族显式声明 `type_="Continuous"` 并接上 d/p/q/r。

**验证**：密度对 y 的积分与 `F(hi)-F(lo)` 一致（4e-6 内）；`d` 与 `dF/dy` 一致（相对 1e-5 内）；F(0)=0、F(10^30)=1；
`q∘p` 往返 1e-16；**F 与 pSHASHo(log y) 逐点差 0.0**。

**里程碑**：`_build_rqres_callable` 覆盖 **146/146** —— 全库每一族都有分位数残差；`has_dqr` **146/146**。

**测试**：新增 `test_logshasho_is_a_density.py`（9 例）。其中"总质量=1"必须在 y=1e30 上断言：tau<1 时 sinh-arcsinh 的尾比正态重，
F(1e10) 仍有 0.999961——这是族的性质，不是缺陷。
