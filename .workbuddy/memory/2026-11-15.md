## D2.225 / P0-3：MIXED 语义对齐（发布门禁收尾之三）

**根因重新定位（backlog 描述已过时，同 P0-1）**：DEVELOPMENT_PLAN 要求
「实现 `RS(n1)→CG(n2)` 兼容模式，或改名并隔离实验路由」——但 `mixed_fit`
（`omnilss/algorithms/mixed_algorithm.py`）早已实现 R-compatible
`RS(n1)→CG(n2)`，`fitting.py:1833` 也早已让 `method="MIXED"` 提前 return
`mixed_fit`。真正缺的是 P0-3 验收标准里那句「**与 R `mixed` 数值/语义对照通过**」：
既有 `test_mixed_rs_cg.py` 只验内部自洽（我们自己的 RS→CG pipeline），
从无活 R 对照。另外残留一套矛盾语义：`_fitting_utils._apply_method_step`
的 `MIXED → 0.75 damped RS` 分支 + `fitting.py` 包装 docstring 的
「75% step (damped RS, experimental)」——`MIXED` 走 `mixed_fit` 提前 return，
内联 IRLS 循环永不以 MIXED 执行，该分支是**死代码**且与出货行为矛盾。

**R 侧关键事实**：`mixed()` 不是导出函数，是 `gamlss()` 内部的局部函数
（`R/gamlss/R/gamlss-5.R:163`）：
`mixed <- function(n1=1,n2=20){ RS(n.cyc=n1); CG(n.cyc=n2) }`。
`gamlss()` 用 `substitute(method)` 对 `c("RS()","CG()","mixed()")` 做 pmatch，
因此活 R 探针必须传**字面** `method=mixed(1,4)`（不能用 `eval(m)` 变量）。
实测 R 4.6.0 / gamlss 5.5.0 / gamlss.dist 6.1.1 / set.seed(1) 的 80 点样本：
`mixed(1,4)/(2,3)/(1,0)` 的 mu/sigma 系数与 deviance 全部落表。

## D2.231 / ZABI 收敛探测：R 侧向量化缺陷 + bd kwarg 静默忽略修复

**目标**：冻结清单里 ZABI 是 pending（备注「需 binomial 两列/bd 负载」）。探测结论：
**不能晋级**（R 侧缺陷），但顺带发现并修复了一个真实 API bug。

**发现 1（产品缺陷，已修）**：`gamlss(..., bd=10)` **kwarg 被静默忽略**。
它落进 `**optimizer_kwargs`，而 `_resolve_fixed_parameter_values` 只看 data 列 /
constructor / `fixed_parameter_defaults`（ZABI 的默认是 `bd=1.0`）→ 拟合用 bd=1，
所有 y>1 观测密度为 0 → **deviance=inf**，mu 漂到边界（系数 15）。把 `bd` 作为
**data 列**传入则正常（dev 469.22）。修法：family 解析后，把名称命中
`family.fixed_parameters` 的 kwarg 并入复制后的 data。修后 kwarg 与 data 列**逐位一致**
（dev 469.2173、系数相同、收敛）。测试
`test_binomial_zero_variants_bd.py::TestFit::test_bd_keyword_is_forwarded_like_a_data_column`。

**发现 2（R 侧缺陷，ZABI 不能作 golden）**：即便 bd=10 正确，我们收敛解
（dev 469.2173，mu [0.2316,0.5414]）与 R（dev 469.4568，mu [0.23252,0.53496]，
mu 系数差 6.4e-3）不同。根因在 R：
- R 的向量化 `dZABI` 用 `dBI(0, bd[x!=0], mu[x!=0])` 算 hurdle 归一化项，而 `x` 是**标量 0**；
- R 的 `dBI` 末尾 `ifelse(x < 0, 0, fy)` 在 x 标量、fy 向量时**返回长度 1**（R 的 ifelse 取 test 长度），
  于是把**第 1 个观测**的 `(1-f0)` 循环给所有正观测；
- 标量 `dZABI` 正确且与我们的逐位一致（mu=0.2644/sigma=0.2167 处：R 标量 0.2215466 = 我们；

## D2.243 / P3-2 收尾：gen.Family 可拟合性（导数按 R 语义包装）

**先查真源再动手**：覆盖工件显示 gen.Family 早已 surface=public_api、kernel=implemented、
parity=tested；test_family_generator.py 也已有 d/p/q 对活 R 的对照（1e-10）。所以
「实现 gen.Family」字面上已完成——**但那个 parity 只覆盖 dpqr，不覆盖拟合**。

**发现的真实缺陷**：Family() 构建 GeneratedFamily 时把基族的 score_functions /
hessian_functions **原样复制**。而 score 的签名是 (y, mu, sigma...)，拟合路径传入的是
**原始 y**；与此同时 g_dev_inc 用 -2*d(y) 内部做 log 变换。结果：梯度在原始尺度、deviance
在变换尺度，两者不一致。实测同一 logNO 样本（n=80, seed=42）RS 拟合：
- 我们 dev **413.4697**，系数 mu [1.7398, 0.6668]、sigma -0.1978（完全离谱）；
- R（gen.Family("NO","log") + RS(n.cyc=100)）dev **140.3831**、mu [0.43908, 0.36313]、
  sigma -0.98997。

**修法**：_wrap_derivative(fn, type) 在调用边界把第一个参数（或 y kwarg）变换后再调用基
函数。变换只作用于 y、不含参数，所以 d/dparam log f_Z(transform(y)) = 基导数在
transform(y) 处取值——与 R 在 body 里 gsub("y" → "log(y)") 完全等价。score 与 hessian
都包（Hessian 同理）。

**修后对照（RS，n.cyc/max_iter=100）**：
- logNO：dev 140.38306650049347（R 140.3830665004935）；mu 差 3.3e-16、sigma 差 1.7e-11。
- logitNO（n=90, seed=77）：dev -188.5069659133473（R -188.50696591334733）；mu 差 3.9e-16、
  sigma 差 8.9e-14。

**测试**（test_family_generator.py 追加）：
1. test_generated_derivatives_see_the_transformed_response：结构不变量——logNO 的
   score_mu/score_sigma/hessian_mu 在 y 处必须逐位等于基族在 log(y) 处（rtol=atol=0），
   防止有人再把未包装函数复制回去；
2. test_generated_family_fit_matches_r_rs：两例活 R 基准（deviance + mu/sigma，2e-4）。

**教训**：**「surface implemented + parity tested」不等于「功能可用」**——parity 覆盖的是
dpqr，拟合路径另有导数契约。判断一项是否真的完成，要看**用户实际调用路径**（这里是
gamlss(y~x, family=logNO())），而不是符号表上的状态。

## D2.244 / P3-3：*.fix 全路由 + 分类预测重建（M3 收口）

**起点**：fitting.py 里有一句显式闸门——mu_fix/sigma_fix/nu_fix/tau_fix 只允许
method='RS'，其他方法直接 ValueError。但 override 本身（改写 family.fixed_parameters +
把冻结值写进同名列）与算法无关，RS/CG/MIXED/JOINT/LBFGS 都通过
_resolve_fixed_parameter_values 读同一通道。闸门是历史遗留，不是机制限制。

**做法**：去掉方法限制，直接对五条路由验证。活 R 基准（NO、n=60、seed=5）：
- sigma.fix=TRUE, sigma.start=0.5：RS()/CG()/mixed(1,100) 三者 dev 均
  67.1324138595735、mu [0.93689395167610423, 0.4565896665555827]、sigma.coefficients=NULL；
- 不给 sigma.start：dev 76.631645584083216、sigma 固定 0.598641360014006
  （R NO()$sigma.initial = rep(sd(y))）。

**过程中发现并修掉 4 个真实缺陷**：
1. **NO/NO2 的 sigma.initial 缺失**：_initial_sigma 的通用回退按「初始 mu 目标的残差」
   计算，而 NO 的 mu 目标就是 y 本身 → 残差 0 → 1e-6 地板。sigma 可估时第一步会自行修复，
   所以 N 年没暴露；sigma.fix=TRUE 时初值即终值 → dev 1.0e13（R 76.63）。补
   NO=sd(y)、NO2=var(y) 两个分支（R 分别是 sd/var）。
2. **cg_fit_v2 给固定参数造伪系数**：coefficients_jax 原对 family.parameters 全量执行
   coefs.get(p, [params[p][0]])，于是 sigma.fix 下 MIXED 报 sigma 系数 [0.5]；R 是 NULL，
   RS 路径本来也不含。改为只对 estimable_parameters 产出系数（拟合值/eta 仍保留全参数）。
3. **cg_fit_v2 的 terms["intercept"] 记错**：写成 _is_intercept_only_formula(...)，
   即「公式是否只有截距」。y ~ g + x 于是被记成 intercept=False，design schema 重建
   预测矩阵时少 1 列（3 vs 4），MIXED 的因子预测直接抛
   PredictionSchemaError "has 3 columns, but saved schema expects 4"。改为
   parse_formula(...).has_intercept。
4. **JOINT 返回最后一轮而不是最优轮**：JointOptimizer 用 Adam + 固定学习率，收敛判据是
   loss 变化 < tol，会在最优附近振荡时提前停；返回的 params 是 post-update、loss 却是
   pre-update。sigma.fix 下实测 dev 67.1638（最优 67.1324），mu 差 7.4e-3。加
   best-iterate 追踪（每轮多一次前向），收敛/超限两条返回路径都返回访问过的最优点；
   修后 JOINT 与 RS 逐位一致，自由 sigma 情形也从 5e-4 收敛到最优。

**测试**（test_p3_fix_methods.py，12 例）：三方法 × {有 sigma.start=0.5 / 无 start}
对活 R 值；JOINT 固定 sigma；flag 类型校验仍生效；CG/MIXED × {contr.treatment,
contr.sum} 的因子拟合并做 predict_params——deviance 与 pred_mu 均对 golden
（contrasts_2026-11-01.json），覆盖「分类预测重建」。

**教训**：**把功能锁在一条路由上，会把其他路由的 bug 一起锁住**。fix 只允许 RS 时，
NO 的 sigma 初值、CG 的伪系数、CG 的 intercept 元数据全都不会暴露；放开闸门才一次
照出来。扩展路由前先问：这条闸门是机制限制，还是历史遗留？

**M3 收口**：P3-1（契约冻结，D2.242）、P3-2（gen.Family，D2.243）、P3-3（fix 全路由，
D2.244）、P3-4（准入，D2.241）全部完成。

## D2.247 / P4-1：gamlss.mx 四个符号补齐（12/12 表面完整）

**R 参照来源**：环境里没装 gamlss.mx，但仓库自带 R/gamlss.mx/R/ 源码，且依赖的 gamlss 与
nnet 都在——source() 后可直接跑出参照值。这让「未安装的周边包」也能做活 R 对照，
不必退回结构性测试。

**实现**（omnilss/mixtures.py，复用已有 MixtureFit 作为对象契约）：
- gamlssMX：K 成分 EM。随机 0/1 掩码初始化 → 每个成分带权拟合 → 后验 W 归一化 →
  prob=colMeans(W) → dev=-2Σlog(rowSums(prob_i·f_i))，收敛 |Δdev|<cc 或 n.cyc。
  支持 formula/family 的列表与常量先验。
- gamlssMXfits：n 次随机起点取最优，extra 记录 dev/seed/which；与 R 一致地丢弃调用方
  传入的 control（R 每次重建 MX.control(seed=...)）。
- gamlssNP：NPML，mixture="np" + random=~1。Gauss-Hermite 节点定初值（tile 后加
  tol·sigma·z），data 扩 K 份加 MASS 因子，EM 权重来自 p_k·f_k，mass points =
  截距 + MASS 系数，df=fit.df+K-1。
- plotMP：返回 20×20 网格 + 每个 mass point 的 stem 几何；装了 matplotlib 时额外渲染
  3D 图。像素一致性按计划不要求。

**对齐结果（活 R，n=200, seed=11 数据）**：
- MX：dev 686.7442332 vs R 686.7442453（1.8e-8）；prob [0.553778,0.446222] vs
  [0.553768,0.446232]；mu 差 ~3e-5；df 7。
- NP：dev 687.9109313 vs R 687.9109314（1e-10）；mu 系数完全一致；sigma 差 8e-7；
  mass points [0.03128966, 2.89773759] 完全一致；df 5、EM 迭代 13 与 R 相同。

**踩坑三个**：
1. dmx 对标量 y 崩溃（values.shape[0]）——既有缺陷，get_pdfMX 一用就炸；改 atleast_1d。
2. NP 的 deviance 权重长度：R 源码里 weightslogl 收到 rep(pweights,K)，但 R 报告的
   G.dev 等于长度 N 权重的正确值（独立复算 687.910929 与 R 的 687.910931 一致）。
   按报告值实现（长度 N），不复制可能存在的回收语义。
3. mass points 索引：term_labels 不含截距，label i 对应系数 i+1；初版直接用 i，
   把 x 的系数 0.3449 当成了第二个 mass point（0.3761 vs 正确 2.8977）。

## D2.248 / P4-2（第一步）：gamlss.add 的 ga/ba 加性项

**先弄清 R 语义**：ga()/ba() 不是拟合函数，而是**项构造器**——它们用 mgcv::gam/bam
（fit=FALSE）造基，再由 gamlss.ga()/gamlss.ba() 对工作响应 z、权重 w 重新拟合。
所以移植的对象是「接口 + 基 + 加权重拟合」，不是 mgcv 本身。

**实现**（omnilss/additive.py + formula_parser）：
- ga()/ba() 返回 AdditiveTerm（内层 formula、解析结果、control），非法 formula 抛错。
- 公式解析新增 ga/ba 分支：把内层公式的项**展开**到外层，所以
  gamlss(y ~ ga(~ pb(x))) 与 gamlss(y ~ pb(x)) 的 ParsedFormula 完全相同；
  has_smooth_terms 的正则也加了 ga|ba，避免被路由成线性项。
- gamlss_ga()/gamlss_ba()：对存储的基做**加权最小二乘**重拟合（法方程正交性可验证）。
  ba 对应 mgcv::bam（big additive models，不是 backfitting），因此与 ga 共用基与拟合路径。

**明确不声称的东西**：mgcv 的 REML 光滑参数选择是另一套估计器，本批不重实现。契约写成
**委托等价**：加性项 == 显式 smooth 公式。测试钉住：
- 解析项逐项相等（ga/ba 各一例）；
- gamlss 拟合的 deviance 与系数**逐位相同**（rel 1e-12 / atol 0）；
- gamlss_ga/gamlss_ba 的 fitted == X@coef，残差对设计列正交（含加权版）。

**覆盖**：gamlss.add 的 13 个缺失中 **4 个转绿**（ga / ba / gamlss.ga / gamlss.ba →
public_api + implemented + tested），剩 9 个：nn / gamlss.nn / fk / gamlss.fk / tr /

**教训**：移植「对第三方估计器的接口」时，先分清哪些是接口、哪些是别人的数值算法。
接口和对象形状可以真移植并验证（这里用委托等价），第三方算法要单独声明边界；
把 mgcv 的 REML 结果说成「已对齐」才是假完成。

## D2.249 / P4-2（第二步）：gamlss.add 的 tr/gamlss.tr（回归树）

**先纠名**：gamlss.add 里的 tr 是 **regression tree（rpart）**，不是截断；截断是另一个包
gamlss.tr 的 gen.trun/trun。两者同名但语义不同，移植前必须分清。

**实现**（additive.py）：
- TreeControl：rpart.control 默认值（cp 0.01、minsplit 20、minbucket round(20/3)=7、
  maxcompete 4、maxsurrogate 5、usesurrogate 2、maxdepth 30、xval 10）。
- RegressionTree：加权 CART，平方误差；切分准则复刻 rpart——improvement =
  (dev_parent - SSE_l - SSE_r)/dev_root，且 improvement >= cp 才保留；候选切点为相邻
  不同值的中点；受 minsplit/minbucket/maxdepth 约束。
- tr(formula, method="rpart", control=...)：项构造器；method 非 rpart 抛 NotImplementedError。
- gamlss_tr(x, y, w, data=...)：对工作响应拟合树，返回 fitted.values/residuals/
  nl.df（= 2*叶数 - 2）/coef_smo，与 R 的返回字段对齐。

**校准踩坑（重要）**：第一次对照用各自 RNG 生成的数据，切点 3.9895 vs rpart 4.0341、
叶均值也不同，几乎误判为准则不一致。把**同一份数据**导出给 R 后，rpart 给出
3.9894619305 / 0.98361426 / 2.96683439，与我们的树**逐位相同**。
教训：跨语言数值对照必须喂同一份输入，否则会把采样差异当成算法差异。

**边界（显式拒绝，不近似）**：
- tr 项**不能直接写进 gamlss() 公式**：R 用 backfitting 每轮重拟合树，本项目是一次性
  设计矩阵联合拟合，且树的预测需要独立 schema；解析器对 tr(...) 抛 NotImplementedError
  并提示改用 gamlss_tr()。这是能力边界，不是隐藏 bug。
- xeval（R 的预测分支）、因子变量切分、surrogate splits、xval 交叉验证均未移植，
  分别抛错或仅保留签名。

**名称冲突**：包内已有 gamlss_tr.py（截断包实现），子模块导入会把 omnilss.gamlss_tr

## D2.250 / P4-2（第三步）：fk 自由节点组（5 个符号）

**基与语义**：截断幂基 X = [1, x, ..., x^degree, (x-k)^degree·I(x>k), ...]。
fitFixedKnots 是固定节点的加权最小二乘；fitFreeKnots 先优化节点位置（最小化 RSS）
再重拟合；fk/gamlss.fk 是 R 在 backfitting 里的接口。

**实现**（omnilss/freeknots.py）：
- fitFixedKnots：返回 fitted/residuals/df(=rank)/rss/coef/sigma/deviance（高斯 deviance
  公式 n log2π + 2n logσ + rss/σ²）。
- fitFreeKnots：1 个节点用有界标量搜索；多个节点用缩放空间 L-BFGS-B **确定性多起点**。
  df = 固定拟合 df + 节点数（与 R 一致）。
- fk()/gamlss_fk()：R 用 gamlss 环境里的迭代计数器决定首次固定、之后自由；Python 没有
  那个 frame，用显式 first_iter 参数表达（默认 True）。nl_df = df - 1。
- centilesTwo：二维网格上预测全部参数 → q_family(cent, ...) → 掩码 + 可选绘图。
  掩码用「缩放空间最近邻距离 > dist」。

**对齐结果（同一数据，seed 3, n=100, y=sin(x)+N(0,0.2), degree=1）**：
- fitFixedKnots(knots=3,7)：rss 39.690485586883、coef 四项与 R **逐位一致**。
- fitFreeKnots(1 个节点)：bp 4.4811375530、rss 30.709061237852，与 R **逐位一致**。
- fitFreeKnots(2 个节点)：R bp [5.2296934754, 7.9267859854] rss 9.987674925832；
  我们 bp [5.2279, 7.9284] rss 9.987781（相对 1e-5）。**目标函数一致**——在 R 的最优点上
  我们的 rss 与 R 相同到 1e-12；差异只来自优化路径。
- centilesTwo 的掩码与 mgcv::exclude.too.far(dist=0.01) 在夹具上**逐格一致**（33/35，
  保留 (3,3)/(4,3) 两格）。

**踩坑**：单起点 L-BFGS-B 在 sin(x) 夹具上停在 rss 10.0108（R 的 optim 到 9.9877），
一开始像「准则不对」。先把目标函数在 R 的节点处求值（9.987674925832 一致）证明目标相同，
再改多起点把优化器补齐。教训：**目标一致 ≠ 优化路径一致**；先验证目标，再谈优化器。

**边界（显式拒绝）**：base="Bbase"（B 样条设计阵）、gamlss.fk 的 xeval 预测分支、

## D2.251 / P4-2（收尾）：nn/gamlss.nn 神经网络项

**R 语义**：nn() 是项构造器，gamlss.nn() 调用 nnet()——单隐层网络，BFGS 从随机权重起步，
后续 backfitting pass 复用上一次的 Wts。

**实现**（omnilss/neural.py）：
- NeuralNet：单隐层 logistic 单元（size）、线性输出（linout，默认 TRUE）、可选 skip 连接、
  权重衰减；损失 sum(w·(y-f)²)/n + decay·sum(wts²)；scipy L-BFGS-B，seed 控制初始化。
- nn()/gamlss_nn()：项 + 回调；warm_start 显式表达 R 的权重复用；nl_df = 权重个数。
- 支持 linout=False（输出 logistic 有界）。

**明确不声称**：不是 nnet 的逐位移植——优化器、随机初值、内部缩放都不同。契约是**功能**
层面：逼近质量、确定性、warm start、衰减、skip-only 退化为线性回归。测试钉住：
- sin(x)+N(0,0.1) 上 R² > 0.95（实测 0.9808，size=5）；
- 同一 seed 逐位可复现；
- warm_start 后 R² 不下降；
- decay=0.1 的权重范数小于 decay=0；
- size=0+skip=True 与线性回归 lstsq **逐点一致**（atol 1e-5），nl_df=2；
- linout=False 输出严格在 (0,1)；
- nl_df == 权重数（n_in·size + 2·size + 1）。

**边界（显式拒绝）**：nn() 内嵌 smoother、非数值预测变量、gamlss.nn 的 xeval 预测分支、
nn(...) 直接写进 gamlss() 公式（联合设计矩阵不能每轮重训网络）。

**教训**：对「第三方训练模型」（nnet/BFGS）不要假装逐位对齐——实现接口 + 功能契约，
把数值边界写进文档和测试。这与 ga/ba（mgcv REML）的处理一致。

**里程碑效果**：gamlss.add **15/15 surface 完整**（第 4 个完整包，前三个 cens/tr/mx）。
M4 缺口 105 → **103**；首个工作项转为 gamlss.spatial（6）。测试 test_gamlss_add_nn.py 9 例。

## D2.252 / P4-3：gamlss.spatial（MRF/MRFA/gmrf/几何，6 个符号）

**模型**：y = Xβ + b + e，b ~ N(0, sig2b·G⁻¹)，e ~ N(0, sig2e·W⁻¹)。X 是区域指示矩阵，
G 是邻接/多边形构造的 GMRF 精度矩阵。
- MRF：对 (log sig2e, log sig2b) 最大化边际（Q-function）似然，有界优化；支持
  sig2e.fix / sig2b.fix / penalty / weights / area 超集。
- MRFA：交替法——给定 lambda 直接解，或迭代 lambda=sig2e/sig2b，或按目标 df 用特征值
  edf(lambda)=df 求根（brentq）。
- gmrf/gamlss.gmrf：项 + 回调，Q 走 MRF、A 走 MRFA，并复刻 R 的 adj.weight 重试
  （|beta|≥20 或 beta<1e-8 时放大权重重拟合）。

**R 参照的取得方式（关键）**：环境里没装 spam，而 R 源码用 as.spam/diag.spam/spam 存储矩阵。
这三个在本模型里只做**存储包装**，于是 source 前把它们定义成 identity，R 的 MRF/MRFA 就能
跑出真值——不是自造参照，是同一份算法源码在缺依赖时的等价运行。

**对齐结果（3×3 rook lattice, n=200，同一份数据导出为 golden 夹具）**：
- MRFA：sig2e/sig2b/df/lambda/deviance **完全一致**，beta 最大差 2.2e-16；
  df=6 模式 lambda 4.8106479481（差 7e-10）、deviance 221.2463447052；
  lambda=2 模式 df 7.3299654745、deviance 202.3393301002，完全一致。
- MRF：beta 差 ~2e-8，sig2e 相对差 2.5e-7，sig2b 1e-6，df 1e-6，deviance 1e-8
  （优化器不同但收敛到同一点）。

**几何辅助**：
- polys2polys：支持已命名的 mapping/序列，也支持 duck-typed 的 sp 对象
  （polygons[i].coords），不引入 sp 依赖。
- draw.polys：返回 xlim/ylim、多边形字典、values 与颜色映射（MRF 或命名向量），
  可选 matplotlib 渲染；像素级一致按计划不要求。

**边界（显式拒绝）**：gamlss.gmrf 的 xeval 预测分支、gmrf(...) 写进 gamlss() 公式
（联合设计矩阵不能每轮重估空间场）、真正的 sp 对象直接传入（需先转坐标列表）。

**覆盖**：gamlss.spatial **9/9 surface 完整**（第 5 个完整包）。M4 缺口 103 → **97**；
首项转为 gamlss.foreach（5）。测试 test_gamlss_spatial_models.py 8 例 + golden 夹具。

## D2.253 / P4-4：gamlss.foreach（5 个符号）+ SEP3/SEP4 Hessian 缺陷

**交付**（omnilss/foreach_tools.py）：
- fitQR：SEP3，sigma=tau=1、nu=sqrt((1-q)/q) 固定，逐分位数返回模型（R 的分位数回归技巧）。
- fitRolling：逐窗口重拟合，预测下一观测，记录各参数 + GDincr；默认索引为 R 的
  1-based 行名 window+1..N。
- NonParametricBoot：行重采样 B 次重拟合，收集系数与预测参数；失败复制计入 failed。
- BayesianBoot：Rubin 的 Dirichlet(1) 权重（乘 N），同结构。
- centiles.boot：重采样后重算 centile 曲线，支持 calibration（残差分位 → 正态 CDF 映射）。

**过程中发现并修掉一个真实缺陷（SEP3/SEP4）**：这两个族由 build_ad_family 自动微分
生成 hessian，得到的是**观测信息**；而 R 的 SEP3.R/SEP4.R 用 **Fisher 近似**
d2ld*2 = -dld*²（下限 -1e-15）。当 tau=1 时 SEP3 退化为非对称 Laplace，对数密度对 mu
分段线性，AD 二阶导**恰为 0** → IWLS 权重塌陷，mu 一步跳到 -1.2e6、deviance 1e8，
而 R 正常收敛。修法：SEP3/SEP4 的 hessian_functions 改为 -score²（下限 -1e-15），
与 R 一致。修后 fitQR 的 deviance 与活 R 对齐到 1e-5：
q=0.25 413.15606、q=0.5 382.60459、q=0.75 413.89298。

**系数不与 R 断言（诚实边界）**：非对称 Laplace 的目标是折线（kink），R 自身报告的
deviance 也不等于「最终系数处」的 deviance（我们复算 R 的系数得到 382.7005，而 R 报告
382.6046）——两边都是「最后一次内层 IWLS 的 deviance + 外层系数可能停在相邻折点」。
所以测试钉 **deviance 一致** 与 **分位数语义**（y<fitted 的比例 ≈ q，误差 <0.1），
不钉系数。

**bootstrap 的契约**：随机过程，R 的 foreach 顺序/随机数不可复现；测试钉形状、
同 seed 可复现、bootstrap 系数均值接近原拟合、失败计数透明。

**覆盖**：gamlss.foreach **13/13 surface 完整**（第 6 个完整包）。M4 缺口 97 → **92**；
首项转为 gamlss.prepdata（19）。测试 test_gamlss_foreach.py 10 例 + QR golden 夹具。

**教训**：AD 自动生成的 Hessian 是**观测**二阶导；若 R 的族定义用 Fisher scoring
（d2ld*2 = -dld*²），在特殊参数点（如分段线性）AD Hessian 会退化为 0，导致 IWLS 崩溃。
移植 AD 族时要对照 R 的 d2ld* 定义，不能默认二阶导就是 Fisher 信息。

## D2.266：cens/tr 证据升级 + 一个真实缺陷（trun 的 q/r）

**先纠正一个 schema 事实**：盘点工具里的 "golden" 只对 **family 符号**可达
（parity = `golden:{r_consistency}`，来源是 `fixtures/r_golden/regenerated/manifest.json`
里的 family 用例）。cens/tr 的 13 个符号 r_family 全是 None，parity 只有
r_consistency_test / tested / unverified 三档——所以对它们 "升 golden" 字面不可达。
能达到的最高档是 `r_consistency_test`，于是按这条路做。

**新增 2 个活 R 模块**：
- `test_r_consistency_gamlss_cens.py`：cens.d / cens.p / cens.q / gen.cens 对
  vendored 源码（3 种删失类型）。注意 R 的 cens.p 对**非事件行用 runif**，所以只比较
  status==1 的行；密度全量比较（1e-12）。
- `test_r_consistency_gamlss_tr.py`：trun.d / trun.p / trun.q / trun / gen.trun
  对 vendored 源码（left/right/both）。trun.r 是随机、fitTail* 是优化包装，保持 tested。

**升级过程中发现的真实缺陷**：我们的 `gen_trun(...)["qNOtr"]` 返回的是**基族**的
qnorm（-1.28/0/1.28），而 R 的 gen.trun 是 `qNOtr <- trun.q(...)`（截断后的分位数
0.1257/0.8884/1.1456）。根因在 `trun()`：注释写着"R 的 trun() 只重生成 d 和 p"——
这对**拟合族对象**成立（R 的族里根本没有 q），但 gen.trun 明确用 trun.q/trun.r 赋值
qNOtr/rNOtr。于是 family.q/r 用了 base 的，导致截断族的预测分位数会落到支撑集外。
修法：`trun()` 的 q/r 改用 trun_q/trun_r；同时把断言"q 保持基族"的旧测试改成
"q 必须截断感知"（旧测试编码的正是这个错误认知）。

**parity 结果（恰好等于实际比较的符号）**：
cens 4/5 [cens.d, cens.p, cens.q, gen.cens]（`cens` 族构造器仍 tested）；
tr 5/8 [gen.trun, trun, trun.d, trun.p, trun.q]（trun.r/fitTail/fitTailAll 仍 tested）。
8 个周边包的盘点动作**全部 hold**。

**教训（又一次）**：文档字符串里点名符号也会被当成证据——第一版在 cens 模块里写了
"`cens` (the family constructor)"、在 tr 模块里写了 "fitTail* optimisers"，这两个符号
立刻被误标为 r_consistency。改完措辞、只用泛指描述后，parity 集合才与实际比较一致。
## D2.267 / P6-1：log_bessel_kv 的 JAX 原生实现——精度达成、性能不达标，未启用

**做了什么**（新模块 omnilss/bessel_native.py，默认路径不变）：
- 三分区原生 log K_nu：x>=15 Debye 渐近（40 项，log 空间，因为 K_20(1000)~1e-436
  会先下溢）、3<=x<15 在 u=ln x 里对 y''=(x^2+nu^2)y 做 16 阶 Taylor 传播（从 x=15 的
  渐近初值向内推进；K 是内推的支配解，稳定）、x<3 小参数级数（K_0/K_1 闭式 + 整数阶
  上递推；分数阶用 (I_{-nu}-I_nu)/sin(pi nu)，注意要带上 Gamma 的符号）。
- 验收工具 tools/bessel_native_scan.py（mpmath 40 位参考）+ 工件
  docs/development/bessel-native-2026-11-15.json。
- 测试 test_bessel_native.py（21 例，含接缝、半整数闭式、vmap、梯度恒等式）。

**验收 1（网格精度）：通过**。nu in [-5,20] 步长 0.5、x in [1e-8,1e3] 25 个对数点
（1275 点），以 K 的相对误差计（log K 在 K~1 处趋零，按 log 求相对误差是条件数假象）：
最差 5.68e-14，分区 series 5.7e-14 / ode 4.1e-14 / asymptotic 1.4e-14，0 个超 1e-12。

**验收 2（Sichel 拟合周期）：不通过**。n=40、SI、max_iter=1：
scipy 回调 5.31 s，原生 371.46 s（慢 70x）。单次调用反而是 0.45ms vs 0.27ms
（只慢 1.7x），真正的问题在拟合循环里：核按观测逐点求值、70 步 ODE 逐元素付费，
而回调的 vmap_method="expand_dims" 把整批合一次主机调用。

**结论**：默认 bessel.log_bessel_kv 保持 scipy 回调（fail-closed），原生核作为
opt-in 实验模块保留（GPU/融合场景才有意义）。P6-1 的「去 pure_callback」只完成一半，
按 D2.235 的先例把验收标准写实，而不是硬勾。

**顺带发现（有价值，未启用）**：GIG/SI 的密度把 c=K_{nu+1}/K_nu 放进指数，尾部系数
可达 ~300，所以「两个 log 相减」的 4e-14 会被放大到 ~5e-12（dGIG 在
mu=2,sigma=0.5,nu=1,x=0.005 处实测 4.9e-12）。用 ODE 传播的斜率直接算
c=(nu-y'/y)/x 可得 5e-16，同一点降到 1.1e-13。原生模块里的 log_bessel_kv_ratio 就是
这条路径（nu<0 用递推 K_{a-1}/K_a=c-2a/x；(-1,0) 无相邻阶恒等式只能退回对数差）。
若将来启用原生核，GIG/SI/SICHEL 的 c 必须走这个接口。

**教训**：核级基准会骗人。单次调用只慢 1.7x，整条拟合却慢 70x——因为回调把 vmap
批成一次主机调用，而原生核按元素付费。验收必须测真实工作流（这里是「一次拟合」），
不能只测孤立的 kernel 调用。
