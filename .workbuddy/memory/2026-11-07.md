## D2.211 build_ad_family 支持族闭包（运行时构造的族终于能被 AD 求导）

- 新入口 `build_ad_family(source_family=<FamilyDefinition>)`：把族自己的 `d(y, log=True, **params)`
  闭包包成标量 log-density，再 `jax.vmap`/`grad` 出 score。适用于 `trun()`、`cens()`、调用方自建的
  FamilyDefinition —— 这些族没有手写核，也不在任何按名查表的注册表里。
- 未显式给的 `name/parameters/family_class/type_/links/link_*/fixed_parameters/
  fixed_parameter_defaults/constructor_parameters/d/p/q/r` 全部从 source 继承。
  **p/q/r 必须继承**：AD 化副本若丢掉截断 CDF，残差会静默退回基族。
- **dataclass 额外字段也复制**（`TruncatedFamily.truncation_type/base_name/truncation_parameters`、
  `CensoredFamily.censoring_type`）。真实踩坑：第一版只继承 17 个标准字段，`base_name` 落到默认 `"NO"`，
  `_start_family` 于是把 WEI3tr 当 NO → 初值 exp(y) → initial deviance **186276**（正常 30.95）。
  修法：`dataclasses.fields(source)` 里不在标准字段集合的都透传。
- `hessian_from_score`：source 模式默认 True → `hessian = -score²`。原因：AD 的原始二阶导是**观测信息**，
  可以为正 —— 截断 WEI3 在 mu=4.96 处 `d2l/dmu2=+0.099`，RS 的 working weight 变负后拟合发散到 mu=166；
  gamlss 对一切数值微分族固定用 `d2ldx2 = -(dldx)²`。显式 `hessian_overrides` 仍然优先。
- 验证（数值）：WEI3 闭包族 score 与基族解析 score 一致（rtol 1e-8）；截断族 score 与截断对数密度的中心差分
  一致（相对差 1.6e-9）、与基族 score 不同；`gamlss(method="RS")` 用 AD 闭包族得 **5.01949 / 2.18715,
  dev 29.63580**，数值 score 族 **5.02655 / 2.17615, dev 29.63587**（同一最优点）。
- 兼容性：原四参数内核形式不变（`type_` 默认由 None 解析回 "Continuous"），位置调用 `build_ad_family(GPFamily, ...)`
  仍可用；`source_family=None` 时行为与之前完全一致（hessian 用 AD 原始二阶导）。
- 新增 `omnilss/tests/test_ad_family_closure.py`（12 例）：密度/元数据继承、score 对齐、scoring hessian 默认值、
  `hessian_from_score=False`、截断族求导与 CDF 保留、dataclass extras、无注册表条目族、override 优先、
  缺 d 的报错、旧内核 API 不变、AD 化截断族收敛到同一最优点。

## D2.212 gamlss.tr fitTail / fitTailAll（2 个符号；闭环 D2.208 的受阻项）

- D2.208 记「因截断族拟合坏，`fitTail`/`fitTailAll` 暂时无法交付」；D2.209–211 把初值映射、
  数值 score、AD 闭包求导修通后，本批交付。`missing` **219 → 217**，matched 861 → 863。
- **结构照抄 `R/gamlss.tr/R/FitTrunTail.R`**：`tailFun` 取排序后的上/下尾 `howmany` 个；
  `typetrun` 与 tail side 相反（right→left）；阈值 `mY = ys[n-howmany]`，若与 `mYp1` 相等则
  减去 `sum(diff(ys[(k-5):(k+5)]))/100`（R 1-based 闭区间 → Python `[k-6:k+5]`）；
  `howmany<=5` / `length(Y)<=5` 都 stop；`fitTailAll` 的 `rest=howmany-(npar+start)`、
  `per` 从 `howmany` 递减到 `npar+start+1`、`colnames=names(FAM$parameters)`、
  `ts(start=npar+start+1, end=howmany, frequency=1)`。R 的 `ts()` 会丢 rownames（实测返回空），
  我们仍按源码意图保留 `rownames`。
- **拟合**：R 的 `gamlssML` 是 link 尺度 `nlminb`/`optim` 数值最大化；我们用同样的 link 尺度
  `L-BFGS-B`，但梯度取 **D2.211 闭包 AD 族的解析 score**（`d dev/d eta = -2*sum(score)*dpar/deta`）。
  **必须解析梯度**：截断似然在参数角落无上界（`1-F(par)` 塌缩），数值差分会踩进 NaN →
  `scipy` 报 `ABNORMAL` 且停在中途的初值上（实测 5 组初值有 3 组完全不动）。换解析梯度后
  5 组初值全部收敛到同一点，AD score 和 ≈1e-6（驻点，不只是 `converged=True`）。
- **活 R 对照的关键教训**：R 的 `gamlssML` 在**某些数据**上对截断族确实收敛失败（mu→0，
  `optim code=1 false convergence`），最初用 R 自己 `set.seed(42); rweibull(...)` 的数据踩到这个坑，
  一度误判「R 数值不可作 golden」。**把 Python 生成的同一份数据通过 JSON 传给 R** 后，
  R 正常收敛，数值 parity 成立：mu **3.43380224 vs R 3.43380268**（rel 4e-7）、
  sigma **3.24455479 vs 3.24455545**、dev **38.69808560049136 vs 38.69808560049158**；
  R 自己的 `dWEI3`/`pWEI3` 评我们的系数得 dev **38.698085600491375**（1e-14）；
  `fitTailAll` 的 5×2 矩阵与 R 逐项一致（1e-6）。**「R 没收敛」先换同一份数据再下结论**。

## D2.213 gamlss.mx 访问器 get_pdfMX / get_cdfMX / get_pdfNP / get_cdfNP（4 个符号）
