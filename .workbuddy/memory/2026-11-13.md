## 交付：`tools/run_full_baseline.py` 单一前台编排脚本（根治后台进程被杀）

- **根因**：agent 回合切换/compact 杀后台进程组，4 个独立后台 job 活不过 >1h 整片时长。
  解法 = **单一前台进程**拥有并阻塞等待自己的 4 个子进程；在**本地终端**跑（无 CodeBuddy
  回合边界），或在上下文短、不发生回合边界的新会话里作为单个后台任务跑。
- **脚本要点**（`python tools/run_full_baseline.py`，默认 4 片）：
  - 复用 `pytest_shards.py` 的确定性分片（整片模式，一次冷编译）；每片独立
    `OMNILSS_MODEL_DB_PATH`（避开 D2.216 sqlite 写锁）；stdout 直接写 log 文件（实时落盘）。
  - **env 纪律固化**：唯一 override 是独立 DB，`JAX_ENABLE_X64` 显式剥离。命令与 D2.214
    成功配方一致：`python -m pytest @tmp/full_baseline/shardN.txt -q -W ignore -p no:cacheprovider --tb=line`。
  - 前台 `wait` 全部片 → 打印每片 rc / 100% / FAILED 清单 → 写 `verdict.json`。
  - **计时 flaky 单独分类**：`test_performance_benchmarks.py` / `test_performance_snapshot_freeze.py`
    的失败归为 timing flaky（提示单跑复核），不改阈值；`result: OK` 仅当全片 rc=0、
    零 FAILED、都到 100%。
  - CLI：`--shards N`（默认 4，8 与 CI 门禁一致）、`--check`（分片自检不跑）、
    `--print-only`（打印命令不跑）、`--timeout`（默认 7200s）、`--out-dir` / `--python`。
- **验收**：新增 `omnilss/tests/test_full_baseline_runner.py` 5 例全过，钉住
  `shard_env` 剥离污染 env / 独立 DB / 调用方 env 不变、`build_plan` 确定性无损干净命令、
  `summarize` 区分 timing flaky 与真实失败、`--check`/`--print-only` 不跑套件。
  `--check` + `--print-only` 实测命令干净（零 `JAX_ENABLE_X64`、相对 argfile 路径）。
- **新会话一键命令**：`python tools/run_full_baseline.py`（本地终端保持打开直到打印 verdict）；
  先看命令用 `--print-only`，只验分片用 `--check`。
