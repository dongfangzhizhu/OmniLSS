## D2.131a 交付：`mu/sigma/nu/tau.start` 用户入口

### R 语义（先查源码，不猜）
`gamlss-5.R`：`mu.start` 标量 → `rep(x, N)`（:1028），向量原样用；尺度是**参数尺度**
（与 `family$mu.initial` 同一尺度，`eta = mu.linkfun(mu)`，见 :431）。四个参数同构：
sigma :1061、nu :1095、tau :1129。`mu.fix` 等在 :996 只做 logical 校验。

### 实现
- `_fitting_init._resolve_start_values(family, start_values, n_obs)`：未知参数名 / 家族固定参数 /
  长度非 1 或 n / 非有限值 全部 ValueError（R 不前置校验，会在密度里炸，报错更难懂）。
- `gamlss(mu_start=, sigma_start=, nu_start=, tau_start=)` → `start_values` dict →
  `rs_fit` / `cg_fit_v2` / `mixed_fit`（mixed 只喂 RS 阶段，CG 阶段继承状态，与 R 相同）。
- RS 的 mu 分支：`eta_target = linkfun(start)` 逐观测交给第一内层步（与 family$mu.initial 同待遇），
  系数只做 WLS 记账。CG 的 mu/sigma/nu 分支同样先 linkfun 再 lstsq。
- `RS_JAX` / `HYBRID` / CG 的 `full_hessian` 后端没有等价状态交接 → 显式 ValueError。

`omnilss/tests/test_start_values_r_parity.py` 12 passed。golden：
`omnilss/tests/fixtures/r_golden/family_start_values_2026-11-01.json`（`tmp/d2131_parity.R` 生成）。

## 复测口径的教训（重要）

- 想把 75 条既有失败复测一遍 ⇒ **单进程跑 75 个 id 不可信**：同一批用例在单进程里互相污染
  （原始 4 分片基线里 pass 的用例，单进程跑会 fail）。用 `pytest @ids.txt` 一次性跑只能当"冒烟"。
- **分片文件里写路径要注意 CRLF**：Windows 文本模式写出的 shard 文件带 `\r`，
  `tr '\n' ' '` 之后路径尾部带 `\r` → pytest 报 "file or directory not found"。
  正确：`tr -d '\r' | tr '\n' ' '`。
- 结论：复测必须**按文件分片**、且与基线用同一分片方式；本轮只完成了部分分片，
  已修的 10 余条以"单文件运行全绿"为证据，整体数字等下一次全量分片跑再定。


## D2.139 交付：CG 路径残差的 KeyError: 'mu'

- 根因：`gamlss()` 的 CG（full_hessian）分支把 `parameter_values` 初始化成空 dict，mu 只放在
  局部变量里；残差调用 `rqres_callable(**{"y": y, **parameter_values, ...})` 因此拿不到 mu，
  直接 `KeyError: 'mu'`（`_fitting_residuals.py:210`）。RS/ML 分支当年把 mu 留在了
  `parameter_values` 里，所以只有 CG/MIXED 触发。
- 修法：残差调用显式传 `"mu": fixed_parameter_values.get("mu", mu)`（固定 mu 优先，与 RS 分支同一规则），
  非 rqres 回退路径同样用它。
- 效果：`test_r_consistency_algorithms[CG-NBI-11/12]` 转绿；CG/MIXED 分支不再因为残差而崩溃。

## 本轮（D2.143b–D2.148）小结：又有 24 条转绿

失败模式高度集中在"断言写死了会漂的东西"，逐个判过之后的结论：

1. **q 的单调守卫必须有前提**（D2.143b）：只要 p 升序就 `maximum.accumulate`，
   但 `q(p_grid, mu_grid, sigma_grid, nu_grid)` 每元素参数不同，量化值本来就不单调。
   现在只在 mu/sigma/nu 全部相同时守卫。误差 3.6e-2 → 1e-15。
2. **R 的 qTF2 不支持 log.p**（D2.143b）：`qTF2(-3, 0, 1, 3, log.p=TRUE)` 直接报
   "p must be between 0 and 1"；pTF2 支持。测试却用 log.p 调 R 的 q —— 永远不可能过。
3. **REML 准则少了惩罚行列式**（D2.146）：`log|A| - log|X'WX| + n·log RSS` 在 λ→0 处两项抵消
   → 单调偏好 λ=0（edf=23=整个基）。正确形式必须含 `-log|λS|₊` 与 `(n-rank)`。
   **这是本轮唯一的模型层 bug，且影响所有用 REML 选 λ 的平滑项。**
4. **两种采样制度不能当同一个数**（D2.144）：`RECORDED`（孤立样本）vs 扫描器登记（全族流），
   差 0.7%~4.2%；GT 更极端（R 自己发散，reported 差 60 倍）。跨制度的"相等"断言实际在断言采样。
5. **容差要跟"信息量"走**（D2.148）：IG/NBI/RG 的系数在平地脊线上，R 自己都在漂（IG 的 mu 漂 7e-4）；
   deviance 才是契约（差 4e-7~1.6e-6），系数容差放宽到 5e-3/2.5e-2。
6. **测试对着不存在的 API**（D2.145）：`fam.logpdf`（没有这个方法）、`fam.p(y=...)`（应为 q=）。
   这类测试从第一天起就没真正验证过属性，失败信息是 AttributeError/TypeError 而不是数值。
7. **幻影测试**（D2.142b）：测试要校验的 tools 脚本 + checklist 文档在仓库里都不存在，git 历史里也没有。

`coverage_diff_report.py` 让报告 JSON 与基线同源，否则 `test_checked_in_baseline_and_report_are_fresh` 仍红。
