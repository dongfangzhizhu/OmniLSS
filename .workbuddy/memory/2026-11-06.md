## 本轮受阻项与一个新发现的**真实缺陷**（记下来给后续批次）

1. **截断族拟合是坏的（P 级，未修）**：`gamlss_ml("y ~ 1", family=trun(par=2, family="WEI3", type="left"))`
   在本会话的验证样本上给出 **mu=224.59 / sigma=219.19**，而活 R 是 **5.4143 / 2.2325**。
   关键判据：**在 R 的解上，我们的截断密度算出的 deviance 与 R 差 1.4e-7（相对 3.5e-9）** ——
   所以 `trun()` 的 d/p/g_dev_inc 是对的，**问题在初值**：族名 `WEI3tr` 落在
   `_fitting_init._initial_mu_target` 的 name 判断链之外 → 走通用 fallback（response 尺度 target=y），
   而 WEI3 的 mu link 是 log → 起点变成 exp(y) 量级（正是 D2.50 NBII 的同一个坑）。
   修法设想：给 `TruncatedFamily` 加 `base_name`，`_initial_*` 查表时先映射回基族。
   **没在本轮改**：`_fitting_init.py` 是核心路径，改动需要全量套件（~1h）与 rsdev 门禁复核。
   → 也因此 `gamlss.tr` 的 `fitTail`/`fitTailAll` 暂时无法交付（它们就是截断族 ML 拟合的包装）。
2. `stepGAIC.CH`：它的作用就是**换项形式**（linear ↔ pb/cs/poly），而我们的设计阵
   `_ALLOWED_FORMULA_FUNCTIONS` 只有 abs/cos/exp/I/log/sin/sqrt，装不了这些项 → 无法端到端验证。
3. `gamlss::bp` 是纯绘图（bucket plot，依赖 gamlss.dist 的 MomentSkewKurt1.RData），无独立数值核。
4. prepdata 的 `y_outliers*`/`data_outliers`/`mcor`/`data_mcor`/`ACE` 依赖
   `y_zscores`(gamlssML SHASHo)、`y_Ptrans`、`y_dots`(ggplots)，同样受阻。
5. `calibration`/`rqres.plot` 依赖 `centiles()`/RNG；`gamlss.lo` 需要复刻 R 的 loess；
   `re`/`gamlss.re` 需要 nlme::lme。
## D2.209 截断族初值映射回基族 + 截断族 rqres 位置参数（核心修复）

- **初值**：`_initial_mu_target` / `_initial_parameter_value` / `_initial_sigma` 入口加 `_start_family()`：
  带 `base_name` 的族（TruncatedFamily）用 `_BaseNameView` **只覆盖 name**，其余属性全部委托原对象；
  非截断族原样返回（幂等）。原因：族名 `WEI3tr` 不在 name 链里 → 通用 fallback（response 尺度 target=y）
  → log link 下变成 exp(y)（D2.50 NBII 同款）。
  效果：WEI3tr 的 mu/sigma 从 **224.59 / 219.19** 变成 **4.9569 / 2.9583**（dev 33.2 → 30.95）。
- **残差**：`trun_p` 的签名是 `fun(q, lower_tail=TRUE, log_p=FALSE, **params)`，而 `_generic_rqres`
  按**位置**传 mu/sigma → 绑到 `lower_tail`/`log_p` 上 → 参数查找报 "missing family parameter 'mu'"，
  截断族的残差全 NaN。修法：新增 `_cdf_values()`，有 `truncation_type` 的族改用关键字传参。
  校验：截断 CDF 与 R 的 `pWEI3tr` 逐点一致（1e-8），修后 rqres == qnorm(CDF) 且全有限。
- **仍未修（下一批）**：即便初值对了，收敛点还是 4.9569/2.9583 而不是 R 的 5.4143/2.2325
  （dev 30.95 vs R 29.79，**加大周期/收紧容差完全不动** → 是算法不动点不是一个提前停）。
  根因：`trun()` 把**基族解析 score/hessian 原样继承**，而 R 的 `gen.trun` 族 `dldm` 是 **NULL**、
  gamlss 改用**截断密度的数值导数**（`numeric.deriv` 前向差分 delta=0.001）。所以我们现在停在
  「未截断 score 方程」的不动点上。修法：给 trun 族换数值 score（并复查 hessian 形式）。
- 回归：初值/截断相关的 14 个测试文件 **207 passed, 2 skipped**（24:45）；全量套件另跑（4 片）。
## D2.210 截断族数值 score + 定位真正的拟合差距（**重要**）

- `trun()` 不再继承基族解析导数，改为 `score = (log d_trun(p+δ) - log d_trun(p))/δ`（δ=1e-3）、
  `hessian = -score²`。依据：R 的 `gen.trun()` 族 **dldm = NULL**，`gamlssML` 是 **nlminb 直接数值最大化**，
  压根没有解析 score。
- 校验：score 与截断对数密度的中心差分一致（rtol 1e-2，差异就是 δ=1e-3 前向差分的截断误差）、
  hessian == -score² 精确、截断 score 与基族 score 不同、右截断/标量参数可用。
- **关键发现：接上 score 后拟合结果一位没变**。monkeypatch 计数证明 `gamlss_ml` 的拟合路径
  **从不调用** `family.score_functions` —— 它通过 **JAX family 构建器**求导，而该构建器按**族名查表**，
  `WEI3tr` 查不到 → 退回基族。于是「梯度来自基族、偏差来自截断密度」，不动点不是截断似然的驻点。
- 三点实测（对我们的 `g_dev_inc` 做中心差分求梯度）：
  `ours dev 30.9541 grad(-2.96,+3.37)` / `R dev 29.7910 grad(+0.81,-0.39)` / `MLE dev 29.6357 grad~0`。
  **R 也不是严格的 MLE**（nlminb 在 7 点样本上的容差），真正的解是 29.6357。
- 下一步（核心改动，需单独一批）：让 `build_ad_family` 能对传入 FamilyDefinition 的**闭包 d** 求导，
  而不是按名重建；否则任何「运行时构造的族」（trun/cens/自定义）都会用错梯度。
- 回归：截断相关 41 passed, 2 skipped；新增 test_trun_numeric_score.py 6 例。
- **更正（D2.211）**：上面「AD 构建器按名查表」的归因是**错的**。实测 `gamlss_ml` 在本仓库只是
  一次 WLS 初值步骤（不迭代：GA 的 `gamlss_ml` dev 229.16 vs `gamlss(method="RS")` 217.40），
  所以改 score 当然没反应。`gamlss()` 的 RS 走 `family.score_functions`，接上数值 score 后截断族
