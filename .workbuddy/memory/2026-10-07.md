## D2.13：BCT 移植 R 解析导数 + 对齐 R 的 link（commit 9cc7cf1）

D2.12 结尾点名的"移植 R 解析导数"。**顺序是先导数、后 link，实测强制**。

### 三步A/B（60 点数据集，RS，n_cyc=500；R 报 199.5647）

| 阶段 | deviance | 与 R 之差 |
|---|---|---|
| 基线（数值导数 + 旧 link） | 200.7269 | +1.16 |
| **仅**解析导数（link 未动） | 209.5343 | **+9.97，反而更差** |
| 解析导数 + R 的 link | 199.5666 | +0.0019（rel 9.4e-6） |

### 核心发现

- **`logshiftto2` = log(tau-2) 隐含 tau>2 的地板。** 解析导数配旧 link 时
  RS 把 tau 的 eta 推到 -35.35 → `tau=exp(-35.35)+2=2.0`，正好撞地板。
  扫tau：2.001→209.79、4→204.43、10→201.45、50→200.03、1e3→199.66、
  1e6→199.637 —— R 的解就在 `tau→∞`（Box-Cox 正态极限）处。
  **旧 link 是"够不到最优解"，不是"收敛慢"。**
- **修复的中间态可能比修复前更差**。导数与 link 是耦合变量，单步只改一个
  会得出误导性结论。A/B 必须留全表中间行，不能只记首尾。
- **抄 R 的导数要连粗糙一起抄**：`d2ldv2 = -7*sigma^2/4`、`d2ldm2`/`d2ldd2`
  都是 R 的粗近似，但它们就是 R 喂给 IRLS 的东西，"改进"会让 parity 变差。
- **R 自身的数值近似会污染我们的验收阈值**。R 的 `dldt` 用硬编码 0.01
  前向步长微分 `log pt`，距其自身密度的精确导数 **1.84e-5**；我们的解析
  score 距 **R** 仅 2.8e-14。
  **断言基准要问"离谁近"，不能默认"离我们自己的密度近" —— 有时 R 才是更远的。**
  D2.12 那条 `rel<1e-6` 的期望就是这么过时的。

### 顺带修的两个真实缺陷（都被本次改动暴露）

1. `dBCT` 截断项调 `scipy.stats.t.logcdf` → 对 traced 值调 `__array__` →
   `TracerArrayConversionError`。`fitting_cg` 恰在 jit 内对
   `family.d(..., log=True)` 求导 → **每个 CG 周期都失败**。
   改用不完全贝塔恒等式（`|betainc - scipy| ≤ 7.3e-15`）。
2. `betainc` 对 `a`/`b` **无梯度**，而 `a=df/2`、df 就是 tau → 按 tau 求导抛
   `Betainc gradient not supported`。给 `_log_pt_t` 加 `custom_jvp`：
   对 `arg` 用解析式 `d/darg log pt = -pdf/pt`，对 `df` 用中心差分
   （**R 自己的 `dldt` 就是这么绕的**）。

### 特殊函数梯度支持（逐个测，不能类推）

- `jax.scipy.stats.t`：只有 `pdf`/`logpdf`，**无** `cdf`/`logcdf`；
  但对**第三参数有梯度**。
- `jax.scipy.special.betainc`：对 `x`（第三参数）有梯度，对 `a`/`b` **无**。
- `jax.scipy.special.polygamma(1, ·)` = trigamma，对第一参数有梯度。
- `digamma`/`polygamma` 与 scipy 一致到 1e-16。

### 纠正一条旧记忆错误

之前记的"`pTF_fixed` 里 `t.cdf` 会崩"—— `jax.scipy.stats.t` 确实无 `cdf`
（这条对），但**导出的 `pTF` 早就自己用 betainc 实现了**（不依赖 `t.cdf`）。
`pTF_fixed` 是从未被导出的坏副本，改 `t` 的别名不影响任何在用代码。

### R 的向量化 quirk

`BCT()$dldv(y, ...)` 向量化调用时，因为 `ifelse(nu != 0, ...)` 用标量条件
坍缩，**返回值与逐元素调用不同**（实测 -0.0692 vs 0.7798, 1.6287, ...）。
R 对照一律**逐元素**求值（`tools/r_parity_batch.R` 也是这么做的）。

## D2.14：扫描器两处误判（commit 366bbbe）

D2.13 后重扫，BCT 从 `pass` 变成 **`skip`** —— skip 的含义是"没测到"，
不是"通过了"，必须查清。两处都是**工具缺陷**：

1. **`identity` link 下探测网格失效**。网格标定从 link 名推区间，
   `identity` → `(-2, 3)`。D2.13 把 BCT 的 `mu.link` 改成 identity 后，
   `mu`/`nu` 探测点变成 `[-2,-1,0,1,2,3]` —— BCT 要求 `mu>0`，
   且 `nu=0` 处 `1/nu` 爆掉 → 所有候选网格评分不可用 → 判 skip。
   **"identity 映射到实数轴"这个假设在"有正值约束"的族上是错的。**
   修法：`_POSITIVE_PARAMS = {"mu","sigma"}` + `_param_range()`。

2. **gate 把 R 自身的粗糙判成我们的缺陷**。标定恢复后 BCT 报
   `tau rel 2.69e-03` —— 那是 R 的 `dldt` 用 0.01 前向步长造成的，
   我们的解析 score 距 R 仅 2.8e-14。
   修法：`_DERIV_TOLERANCE` 按 `(family, parameter)` 登记容差，
   并在失败明细里附原因（防止后人"修"掉这个余量）。

**教训**：
- 工具改动会让"已通过"的族变成 `skip`。看到 skip 要当**未知**处理。
- 判据基准要问"离谁近"：R 的手写近似可能比我们自己的有限差分**更远离**
  真实导数。此时统一阈值会系统性冤枉自己。
- 从元数据（link 名）推参数区间时，要确认那条推论对**全族**成立。

**遗留（下一项）**：BCCG `deriv` fail（sigma 2.88e-01）、BCPE `deriv` fail
（mu 1.20e+00）—— 这两个是**真实缺陷**，需按BCT 的顺序
（先解析导数 → 后 link）移植。R 源码已取到：`BCCG()` 三参数无 tau，
用正态 `dnorm/pnorm` hazard；`BCPE()` 四参数，导数含 `lgamma(1/tau)`
与 `pgamma`。

## D2.15：BCCG / BCPE 密度同源化 + 解析导数（commit d5808b0）

扫描器 `deriv`：BCT/BCCG/BCPE **三族全 pass**（此前 BCCG fail sigma 2.88e-01、
BCPE fail mu 1.20e+00）。

### 两层缺陷，漏项各不相同

1. **密度不同源**（D2.12 的形状已扩散到全簇，但每族漏的东西不同）：
   - BCCG 漏 `-log(pnorm(1/(sigma|nu|)))` → 偏差**恰为常数** 0.20179639
     （= `-log(pnorm(1/(0.65*1.7)))`），与 y 无关，看着无害但污染全部 score；
   - BCPE 漏 `c` + 截断项，且 kernel 写成 `-0.5*|z|^tau` 而非 `-0.5*(|z/c|^tau`
     → 偏差**随 y 变**，网格上 spread **1.539**，直接改变最优解。
   - `dpqr_functions.dX` 一直是对的。现在打分路径**import d/p/q/r 的助手**
     （`_bcpe_c` / `_bcpe_ftrunc_log`），机制上保证一个族只有一个密度。
2. 数值导数 + `mu.link` 应 `identity`（原 `log`）。

### 关键教训

- **逐族查密度同源，不能从一族的结论推全簇。** BCT 修完 ≠ BCCG/BCPE 修完。
- **偏差是常数还是随 y 变，决定危险程度** —— 两种都要查，不能只看"像不像常数"。
- **"我们比 R 好"默认当作可疑**：查证方法 = **把双方系数放到 R 自己的密度函数
  上算**。本次 BCPE 我们 161.9236 < R 162.0165，在 R 的 `dBCPE` 上复核确认
  我们确实更优 → 弱识别平坦区（同 D2.12 的 PE），不是缺陷。
  这步能区分"找到更优解"与"优化了错误的目标"。
- **R 各函数签名不统一**：`d2ldm2` 有的带 `y` 有的不带，且**带 `y` 的值也
  可能不依赖 y**（BCPE 的 `z` 是死代码，y=0.5 与 y=99 同值）。
  用 `names(formals(...))` 查，别猜。
- `dnorm(x)` 漏 `1/sqrt(2*pi)` → hazard 放大 **2.5066**。我自己的探针踩过，
  足以伪装成"R 的导数错了" —— 排查时先怀疑自己的探针。

### 数据要求（Box-Cox 簇）

`y > 0`。R 遇 `y<=0` 直接报 `response variable out of range`，而我们的 `d*`
静默 clamp 成 eps —— **两侧在非法数据上根本没在比同一个东西**。
测试数据必须构造为严格正。

### 验收

60 点严格正数据、RS/n_cyc=500、两侧逐位相同：
`BCCG 166.308044 vs R 166.307802 (rel 1.45e-06)`；

## D2.17（commit `721afcb`）：`BCTo` / `BCPEo` 从无法拟合到可拟合

**现象**：两族在族表可见、能 resolve，但每次 RS 周期抛异常
（`Betainc gradient with respect to a and b not supported` /
`igamma_grad_a not implemented`），从未成功拟合。

**根因**：各自独立重写的 log-pdf 碰到无二阶导的特殊函数
（`betainc(tau/2,·)` / `gammainc(1/tau,·)`）。D2.13 的 `custom_jvp`
只修**一阶**；RS 的 Hessian 对 JVP 再求导就回到特殊函数。

**修复**：(1) log-pdf 委托 `dpqr_functions.dBCT` / `dBCPE`（R 里
`dBCTo` 与 `dBCT` body 逐字相同）；(2) `build_ad_family` 加
`score_overrides` / `hessian_overrides`，带 override 的参数**跳过 warm-up**
（warm-up 的 `_vmap_hess` trace 就是抛错处，即使结果被丢弃）。
两族从 `BCT()` / `BCPE()` 借入 R 闭式导数。

验收：`BCTo` rel 3.00e-05、`BCPEo` rel 3.60e-03（`c_crit=0.001`）。

### 最大的坑：`...` 静默吞掉参数名

`gamlss.control` **没有 `delta` 参数**（签名止于 `save, ...`）。
`gamlss.control(delta=1e-8)` 被 `...` 吞掉，R 静默用默认 `c.crit=0.001`。
我这边传 `c_crit=1e-8` → **两侧停止规则差 1000 倍**，
却据此得出"我们 deviance 一律更低"的结论。

**R 的 RS 判据是绝对量**：`abs(G.dev.old - G.dev) > c.crit`。
我们的是 `abs_change < tol or rel_change < rtol`（绝对**或**相对）。
**parity 对比必须用同一判据。**

R 提前停的证据：R 系数的 score 和显著非零（BCT mu −0.145 / sigma +0.116
/ nu +0.028）→ 不是驻点；`tau` 方向 score 峰值仅 3.9e-9 → 完全平坦。
判定"我们比 R 好"的标准动作仍是**同一密度互评 + score 和是否为零**。

### 其他踩到的 R 语义坑

- `fit[["mu.fv"]]` 是 **n 元素 fitted values**，不是系数对。取 `[1]`/`[2]`
  当截距/斜率重建 `mu(x)` 得 `mu(40) ≈ 71`（`y` 在 [0.4,4]），
  deviance 被抬到 **464**。**用 `y ~ 1` 让 mu 是标量**才能消除歧义。
- `gamlss.family` 对象**没有 `d`/`p`/`q` 槽**（槽列表止于 `y.valid`）。
  `!is.null(o$p)` 为 TRUE 但 `o$p(...)` 报 "attempt to apply non-function"
  （`$` 部分匹配到 `parameters`）。dpqr 是命名空间级 `pBCTo` / `qBCTo`，
  第一参数名是 `q`。
- Python 注册名是**大写**（`BCTO` / `BCTUNTR`），R 风格是混合大小写
  （`BCTo` / `BCTuntr`）。核对覆盖时不要拿 R 名字去比 Python 名字。

### 测试替身不能伪造失败模式

想用 `jnp.round` 当"一阶可导二阶不可导"的替身 → 实测二阶返回 **0**
而不是报错，什么也没复现。裸 `betainc` 也不行 → **一阶就失败**，

## D2.18（两轮）：ST1/ST2 从无法拟合到可拟合 + 正态极限分支

### 第一轮：RS 闭式导数

**现象**：两族每次 RS 周期抛 `Betainc gradient with respect to a and b not
supported`，从未成功拟合。

**根因比 D2.17 更硬**：`_t_cdf_jax` 调 `betainc(df/2, 0.5, x)`，而 `betainc`
对 `a`/`b` 无梯度。Box-Cox 簇里 `custom_jvp` 至少修好**一阶**；**这里连一阶
都失败** → `custom_jvp` 无处可挂（它作用在"已求出的导数"上）。必须抄 R 闭式。

**ST1 vs ST2 的真实差别**：ST2 的 `w = nu*sqrt(lam)*z` 带 `lam`、密度用
`df = tau+1`，`dldm`/`dldd` 多出 `dwdz` 项。**R 的 `lam` 也出现在 ST1 的
`dldm`/`dldd` 里**（尽管 ST1 的 `w = nu*z` 用不到）—— 照抄不"整理"。

**三处刻意保留的粗糙**：四个二阶导全是 `-dldX^2` 夹在 -1e-15；
`dldt` 保留 R 的硬编码步长（ST1 在 tau 上 0.001、**ST2 在 df=tau+1 上 0.0005**，
同一个导数两个步长，是 R 的不一致）；`dldv` 无保护除以 `nu`
（`nu=0` 时 R 返回 `NaN`/`NA`，加"保护"会偏离参照物）。

**发现 R 自身缺陷：`ST2` 的 `dldt` 漏 `dw/dtau`**。R 的 `j` 项差分
`pt(w, df=tau+1)` 时**固定 w**，但 `w` 通过 `lam` 依赖 `tau`。活 R 实测
（y=0.3, mu=sigma=1, nu=0.5）R 0.929927/0.298691/0.083972 vs 中心差分
0.990414/0.328777/0.096027 → **R 自己偏低 6~12%**。中心差分 h 从 1e-3 到
1e-7 完全收敛 → 是 R 的离散化。照抄，登记 `("ST2","tau"): 5e-1`。

### 第二轮：`tau >= 1e6` 正态极限分支 + `ST1` 的 rsdev 定性

#### 教训 1：跨数据比较 deviance 毫无意义（踩了两次）

扫描器**所有族的样本出自同一个 `default_rng(20261006)` 共享流**，
某一族的样本取决于它前面排了多少族。

1. 第一次：拿自己的探针数据比扫描器记录的 R 值（152.39 vs 138.379）。
2. 第二次：跑 `--families ST1,...,ST5` 子集想"快点验证"，结果 R 基准从
   138.379 变成 142.148 —— **子集改变了 rng 流位置**。

**唯一可比口径 = 全族扫描**。要复现某一族的数据，**调扫描器自己的
`_build_jobs`** 导出，不要另起种子"造一份差不多的"。

#### 教训 2：`rel` 偏差的**方向**决定它是缺陷还是发现

只有**我们更高**才是明确缺陷。**我们更低**要先怀疑 R 提前停止。

判据（两步，缺一不可）：
1. **打印 R 的逐迭代轨迹**，看哪个方向被冻结；
2. **用 R 自己的 `d*` 评估我们的系数**（"同一密度互评"）。

ST1 实测：R 在第 5 次迭代停（`tau_eta` 从第 3 次起冻结在 129.2813、
`nu` 一直 0.462，从未被探索）—— R 的判据是**绝对量**
`abs(G.dev.old - G.dev) > c.crit`（默认 0.001），deviance 在 138 量级时
两次迭代差就够小。我们继续下降找到 **134.604639**（低 3.8）。
R 的 `dST1` 在我们的系数处返回 **134.604639**（差 1.3e-07，R 的
`ifelse` 向量化 quirk）→ **同一目标函数，我们确实更优**。ST2 同样。

处置：`rs_family_parity_scan.py` 新增 `_RSDEV_R_STOPPED_EARLY`，
**只对"我们更低"开口**，且要求数字仍与登记一致（漂移即退回 fail），
该族按**登记时的预算**（n_cyc=1000）重跑 —— 否则是拿我们 20 次的平台
比 R 的 5 次停机点。

#### 教训 3：`coefAll()` 在 R 里返回 **link 尺度**，不是自然尺度

R 的 ST1 最优 `tau_eta = 129.28` → 自然值 **1.4e56**。当成自然尺度会把
`sigma = -0.0239`（**负数**）送进密度，静默得到 NaN。
`gamma = 1.404e+00` 这种一眼荒谬的值是唯一的出路 ——
**两侧都用 `[[par]].coefficients`（link）与 `[[par]].fv`（自然）成对打印**。
我们的 `model.coefficients` 也是 link 尺度。

#### 顺带修的真实缺陷：`dST1`/`dST2` 缺 `tau >= 1e6` 正态极限分支

R 的密度是**两套 kernel 加开关**：`loglik <- ifelse(tau < 1e6, <t kernel>,
<loglik2 = pNO+dNO>)`。`ST3`/`ST4` 都有，**ST1/ST2 是仅剩的两个漏项**。

**不是装饰**：R 自己的 ST1 最优解就落在 `tau = 1.4e56`，正在这个分支里 ——
漏掉它意味着我们的密度**在 R 的解处就是错的**。

活 R 两侧（y=0.35, mu=1.2, sigma=0.8, nu=0.5）：
`tau=999999` → -1.779029676131917；`tau=1e6` 与 `1.4e56` → -1.779029378512898。
**差 3e-07，可观测** —— 这是判据成立的前提。
修复后 ours vs R：t kernel 侧 ≤ 1.7e-09（`_t_cdf_jax` 的 `betainc` 在
`df~1e6` 精度下降，**既有**限制）、**正态侧 4.44e-16**。

**但修复没有改变 RS deviance**（ST1 n_cyc=20 仍 140.110594）：
`df = 4.4e6` 的 t **数值上已收敛到正态**，R 的显式分支只是把极限做精确。
价值是对齐 R 在任意 tau 下的密度。

#### 教训 4：特殊函数仍然要逐个测

`_norm_logcdf` 先写 `log(0.5*erfc(-x/√2))` → 实测 `x=-3` 处与 `log_ndtr`
差 **3.90**（`-2.706` vs `-6.608`），**开不开 x64 都一样** → 不是舍入，
是公式写错。改用 `log_ndtr`（正是 R 的 `pNO(log.p=TRUE)` 走的同一条路），
实测 `grad` 与 `grad(grad)` 都有限，能过 `fitting_cg` 在 `jit` 内求导那一关。

## D2.19 补充：全族扫描暴露的第四处根因 —— `ST3C` 的 `tau >= 1` 地板

修完 link + 初值后重跑扫描，`ST3C` 的 `dpqr`/`deriv` **由 skip 变 fail**：

```
ST3C  deriv  fail  tau: max rel 9.697e-02  (analytic [0,0.] vs fd [0, 0.09697])
ST3C  dpqr   fail  d: max rel 8.243e-02; p: 1.589e-02; q: 8.247e-01
```

`skip → fail` 是**信息量增加**（从未测到 → 测到且失败），不是回退。

**定位**（分轴扫描，从"整体不符"缩到"单轴不符"最快）：

```
tau 轴 (nu=1.0, y=0.3):  tau=0.3/0.5/0.7 全返回 -1.2309075820904529（R 各不同）
                          tau>= 1 全部 OK
nu  轴 (tau=2.0, y=0.3):  5 点全OK 到 1e-16
```

→ 地板 `maximum(tau, 1 + eps)` 把 `tau < 1` 的密度压成**常函数**，导数恒 0。
R 的 `ST3C()$tau.valid` 是 `all(tau > 0)`，无地板。改为 `maximum(tau, eps)` 后
**48/48 网格点吻合到 1e-12，max 3.109e-15**。

### 地板类缺陷的通用判据（本轮最可复用的一条）

`SST` 的 `tau >= 2+eps` 与 `ST3C` 的 `tau >= 1+eps` **形状完全一样**
（一行 `jnp.maximum`），**性质完全相反**：

| | R 的边界 | 另一侧 | 地板 |
|---|---|---|---|
| `SST` | `m2` 带 `(tau-2)` 分母 | R 自己 `sqrt` 得 `NaN` 并**直接 abort** | 正当，标的是有效域 |
| `ST3C` | `tau.valid = all(tau > 0)` | 有定义且随 tau 变 | 不正当，删掉整个区域 |

**不能读代码判断，只能实 R 求值。** 判据：**R 在边界另一侧是否真有定义**。

### 本轮第四个假发现（探针侧）

手抄 48 点 `y` 网格只保留 4 位小数（真值`0.4574468085106383`，我写 `0.4574`，
差 4.68e-05）→ 修完地板后残差仍有 **1.66e-03**，一度以为没修干净。
改用 `_family_grids` 导出全精度 JSON 给 R 求值才归零。

**探针精度是parity 结论的前置条件**，与探针路径、探针语义同級。

## D2.20：`TF2` —— 链式法则 + R 的两参数闭式 + `TF` 缺正态分支

**入口信号**：`dpqr` pass + `deriv` fail + `rsdev` rel 2.3e+01
→ **密度对、导数错**。但本轮三处根因里有**两处是密度的问题**。

### 1. 重参数化壳转发裸导数（`TF2` → `TF`）

`TF2` 是壳（`sigma1 = sqrt((nu-2)/nu)*sigma`），但三处score/hessian
把**原始 sigma** 转发给 `TF`，链式法则全丢。

**关键症状：hessian 与转发后的 score 自洽到 1e-11。**
RS 在迭代一个**内部自洽但不属于所最小化密度**的梯度，
`converged=True` + 看似合理的 Hessian 同时成立。

### 2. R 的**两参数闭式** ≠ 我们的四参数 AD 版（最隐蔽）

R 的 `d2ldv2` 里写 `TF()$d2ldd2(sigma1, nu)` —— **只收两个参数**的闭式
`-(2*nu)/((nu+3)*sigma1^2)`。我们转发自己的 AD 版（收 `y,mu,sigma,nu`），
`nu=3` 时返回 `-1.0` 而 R 返回 `-3.0` → `d2ldv2` 差 **13 倍**
（`-0.00983` vs `-0.12802`）。

**签名不同就足以偷换函数，且值差 3 倍。** 这是
"修好 score 后 deviance 反而更差"（3399 → 6835，撞 `nu_eta=-36` 地板）的直接原因。

### 3. `TF` 密度缺 `nu > 1e6` 正态极限分支（D2.18 kernel 开关的漏项）

R 的 `dTF`/`dTF2` 都有 `ifelse(nu > 1e+06, dNO(...), (1/sigma)*dt(...))`。
**而 R 自己的 `TF2` 最优解就落在 `nu = 3.6e20`**（`nu_eta=47.33`）
—— 漏分支意味着我们的密度**在 R 的解处就是错的**：
单点 log-lik `-23.68` vs R `-1.2956`，48 点累加 deviance **2334.79 vs 144.17**。

**必须同步改两处**：`dpqr_functions.dTF`（RS 评估）与
`distributions.TF._log_density`（AD 微分）。**只改一处 = 重新制造密度/导数分裂。**

### 验收

| | 修复前 | 修复后 | R |
|---|---|---|---|
| deviance | 3399.12 | **144.171705** | 144.171705 |
| 密度在 R 系数点 | 2334.79 | **144.171705**（差 6.8e-12） | — |

三个 score 与 `d2ldv2` 现在**逐位吻合活 R**。

### 我们停`nu_eta=240`、R 停 47.33，但 deviance 相同 → `nu` 弱识别平坦

| `nu_eta` | 4 | 10 | 20 | 47.33 | 240 |
|---|---|---|---|---|---|
| deviance | 144.742391 | 144.173133 | 144.171705 | 144.171705 | 144.171705 |

`>= 20` 之后平坦到 15 位数字。R 提前停是 `c_crit=0.001` **绝对**判据
（D2.18 同一模式）→ 断言用**双向带容差**，不是相等。

### 顺带：`TF2$nu.initial=4` 而 `TF$nu.initial=10`

同参数名、同文件、不同值，**不能合并分支**。
R 的 `TF2$nu.linkfun = log(nu-2+1e-05)`（加 `1e-05` 不是 `eps`）——
在 `nu≈47` 处两者都远小于值，**不是根因**，但已核实。

### 本轮三个假发现（第五次栽在探针侧）

1. `max(val, -1e-15)` ≠ R 的 `ifelse(val < -1e-15, val, -1e-15)` ——
   Python `max` 把**所有负值**往上夹，正确的 `-0.02435836` 被夹成 `-1e-15`，
   一度看成实现 bug。
2. `jsonlite` 把 R 的 `NULL` 渲染成 **`{}`** 而非 `null` →
   `float(dict)` 抛 `TypeError`。D2.19 的 SST 探针拿到的是真 `null`，
   **两种形状都要判空**。
3. links 的 JSON 键是 `mu.link`（`as.list` 保名）而我断言 `mu` —— D2.19 已记，
   写测试时没照做。

### `_scanner_sample` 的缓存只装了两族 → 别的模块 import 时静默 skip

D2.19 的 helper 只把 `FAMILIES`（ST3C/SST）写进缓存，D2.20 的四个R-backed
测试首跑全是 skip，**长得和通过一模一样**。`_build_jobs` 本来就全跑，
现在缓存全部族。

**教训：可复用 helper 的缓存范围要匹配它的实际作用域。**

## D2.21：`BI`/`DBI` 的 rel 1.25e+90 —— 是**扫描器**在撒谎，不是族有缺陷

全族扫描报`BI`/`DBI` `dpqr d` rel **1.246e+90**（全registry 最严重）。
逐层查证后：**两个族的 d/p/q 全部正确**，缺陷在 `tools/rs_family_parity_scan.py`。

### 1. 位置传参把`bd` 和 `mu` 送错了参数

R 的签名是 `dBI(x, bd, mu, log)`（**bd 在 mu 前**），
我们的是 `dBI(x, mu, bd, log)`。
`_python_dpqr` 按位置传 `[x, bd_array, *params]` → **`mu` 收到 10**、
`bd` 收到概率。`mu` 被 clip 到 `1-1e-10`，二项系数爆炸。

R 侧本来就按名传（`r_parity_batch.R` 的 `names(aa) <- argnames`），
**Python 侧没有**。已改为 `fn(**kwargs)`，参数名取自 `fam.parameters`。

### 2. 离散族的`y` 网格含非整数

`calibrate` 的二项候选是 `np.arange(n) * (bd/(n-1))`，
`n=8, bd=10` → `0, 1.43, 2.86, ... 10`。
R 的 `dbinom` 对非整数 `x` 返回 **`-Inf`** 并打印 `non-integer x = 1.428571`
→ **8 点里 6 点在 R 侧不可评估**；我们的 `dBI` 用 `jnp.round(x)` 照算。

**两边对"函数是否有定义"都不一致的网格点，不可能产出有意义的 parity 结论。**

### 两个缺陷必须**叠加**才产生 1e90

| | 非整数网格 | 整数网格 |
|---|---|---|
| 错位调用峰值 | **1.2e+90** | 1.4e+02 |
| 后果 | `bd - x_count` 深度负 + `mu≈1` | 仍然错，但不爆炸 |

只修网格 → 留下"错但看着合理"的数字；
只修传参 → R 侧仍无法评估多数网格点。
**"两个bug"最自然的读法是"任一即可解释症状"，这里不是。**

### 教训

- **rel 大到荒谬（1e90）时先怀疑探针**。1e90 不是数值分歧，
  是"参数送错了"的签名。真族缺陷不会有这种量级。
- **R 的形参顺序要逐族查**，不能假设与 Python 一致；
  R 侧按名传参而 Python 侧按位传参，两边可以一个对一个错。
- **离散族网格必须是整数**，`calibrate` 的候选要按 `type` 校验整数性。
- 本轮我自己在测试里翻了 4 次（把plain density 当log、
  `np.exp` 多套一次、`|d|<1` 用在log 上、期望值算错）——
  **每次都是"没看实际数值就下断言"**。D2.19 立的"先查探针"纪律
  这次同样适用到自己新写的测试上。

## D2.22 —— BI/DBI 的 RS 拟合把成功计数当比例（8566.07 → 逐位一致）

`gamlss("y ~ x", family="BI", data={"y":succ,"x":x,"bd":bd})`
报 `converged=True` + deviance **8566.07**，R 同数据 **217.97377537960233**。
三处独立缺陷叠加，任何一处单独存在都仍是坏的：

1. **`_initial_mu_beta` 的 `BI` 分支**：`logit(clip(y))` —— y 是成功计数
   不是比例。R 的 `BI()$mu.initial` 是 `mu <- (y + 0.5)/(bd + 1)`
   （活 R dump 求证）。同文件 `BB` 分支有 `/bd` 但同样缺半计数修正。
2. **`rs_algorithm.rs_fit`**：`other_params`（score/Hessian 的 context）与
   `dev_kwargs`（g_dev_inc）都只从 `family.parameters` 构造，而
   `estimable_parameters` **刻意排除 fixed_parameters** → `bd` 从未到达
   任何一处。`g_dev_inc(bd=None)` 选**Bernoulli** 分支，把计数 7/10 读成 7。
3. **`warm_start_policy.FamilyHeuristicInit`**：给 BI 的是
   `mu = mean(y) = 5.78`，`logit(5.78)`是 NaN → clip 到 +15 → 第一个
   IRLS 步之前就从 `mu=1.0`、dev 21360.6 起步。已把 BI/DBI/BB 加进
   `_NON_MEAN_MU_FAMILIES`。

**诊断轨迹（可分离）**：
```
mu=mean(y)      -> logit clip -> mu=1.0, dev=21360.6
mu=1.0, bd缺失  -> Bernoulli  -> mu 在 1-3e-7 与 3e-7 之间两周期震荡
mu=logit(计数)  ->            -> dev=8566.07, converged=True（报出的 bug）
三处全修        ->            -> dev=217.973775379603 == R
```

### 三条新纪律

1. **`converged=True` 不等于到达极小** —— 它报告步长塌缩。两周期震荡
   的失控过程看起来就是完美收敛。凡 `converged=True` 但目标值明显不合理，
   先怀疑震荡。
2. **固定参数是似然的一部分，必须像估计参数一样传下去**。
   `estimable_parameters` 排除 fixed 参数是对的（不进设计矩阵），但
   `context`/`dev_kwargs` 从 `family.parameters` 取就会连带排除它 ——
   这个耦合**零测试覆盖**，改了没人知道。
3. **分不清"族缺口"还是"拟合缺陷"时，先 dump 双方的参数列表**。
   我们的 `DBI` 与 R 的 `DBI` 连参数个数都不同（我们 `("mu",)`，
   R `(mu, sigma)`）—— 一查就清楚。我却在写断言失败之后才去查。

### R 的二项拟合路径（解除 D2.21 遗留）

`gamlss()` 对二项族**只接受两列** `cbind(success, failure)`，即使
`BI()$y.valid` 是 `all(y >= 0)`：

```
Error in gamlss(y ~ x, family = BI(), data = df_with_bd, ...) :
  y values must be 0 <= y <= 1
```

之前扫描器的 `_fit_data` 发单列 + `bd` → `BI`/`BB` 的 rsdev 一直 skip。
现在 `_fit_data` 发 `fail` 列、`r_parity_batch.R` 按
`payload$response_formula` 拼 `cbind(y, fail)`、我们这侧从同样两列重建
`bd`（两边必须最小化同一个似然）。`BI` rsdev **251.671 vs R 251.671**、
`BB` **203.879 vs R 203.879**，两族首次进入门禁且逐位吻合。

`DBI` 的 rsdev 报 `FamilyCapabilityError`：compat alias 门禁在**正确工作**。
`gamlss()` 不透出 `allow_compat_alias`（只在内部 helper 上），测试因此走
`rs_fit` 而不是绕过 fail-closed 准入。

### 本轮测试失误（又一次印证"先打印实际值"）

四次：
1. `convergence_status()` 返回**布尔**不是词汇字符串（词汇在
   `termination_reason` 上）—— 与 D2.2 记的有出入，已注明。
2. Bernoulli 分支对 `y=7` 给**正**增量 deviance（`(2y-1)*log(0.5)`=+1.386），
   `y=9` 才给 −21.73。**负 deviance 出现在 y=9 上**，这个观察反而成了
   最可诊断的信号。
3. spy 测试对 DBI 记录 0 次调用 —— 因为 `gamlss()` 拒绝 compat alias，
   **长得和"bug 复现"一模一样**。
4. 拿 R 的 DBI 参考值断言我们的 DBI，先 dump 参数列表才发现是族缺口。
