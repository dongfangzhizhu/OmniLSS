## D2 首项：WEI2/PE2 RS 拟合修复（commit 0c94bb2）

- **根因**：WEI2/RGE/PE2 拟合发散不是算法问题，而是 `FamilyHeuristicInit`
  暖启动 `mu=mean(y)` 劫持了 mu 初始化（rs_fit 优先采用 (n,) 形状的暖启动
  mu），族感知 `_initial_mu_beta` 从未运行。WEI2 的 mu 是 rate 参数
  （scale=mu^(-1/sigma)），mean(y) 起点让第一步 IWLS 崩掉、sigma 步爆炸。
- **修复两层**：(1) `FamilyHeuristicInit._NON_MEAN_MU_FAMILIES={WEI2,RGE,PE2}`
  省略 mu；(2) `_fitting_init` 移植 R family 对象的 mu/sigma/nu.initial
  表达式（WEI2: s.Y.s=1.283/sqrt(var(log y)), log mu=-s.Y.s*log(y)-0.5772）。
- **R parity 达成**：WEI2 g_dev 407.0459 vs R 407.0464；PE2 135.7183 vs
  135.7193；系数相对差 <=7e-3（似然面在 (sigma,nu) 平坦所致，验收 rtol 1e-2）。
- **RGE 拟合受 R 阻碍（新定性）**：R 自己无法用 gamlss() 拟合 RGE——dRGE 在
  IWLS 步中硬 stop（x > mu-sigma/nu 支撑域约束），RGE 自采样数据/截距-only/
  显式安全初值全部实测失败。与 GIG/LOGSHASH 同状态哲学。
- 澄清：探针 NO2 g_dev 8.7e6 是模型误设（常方差数据），正确设定 4 轮收敛。
- 测试：`tests/test_rs_fit_wei2_pe2.py`（6 项，含活 R 对照）。
- **调试方法论**：monkeypatch `rs_step` 抓取 `rs_fit` 内每次调用的实际输入输出
  是定位此类"手复现正确、完整拟合发散"问题的关键；手写复现时注意探针 rng
  抽取顺序要与 dump 数据集完全一致（这次吃过亏：432 vs 407 差异纯属数据不同）。
- **流程教训（再次验证）**：新增 tests/ 文件会改变 test_suite_sha256，覆盖工件
  必须与代码同一 commit 再生（这次做对了）。

## D2.2 拟合收敛状态一等化（commit f0069ac）

**触发**：探测 WEI2 时访问 `res.converged` → AttributeError，暴露模型容器根本没有收敛概念。

**根因链**：
1. `GAMLSSModel` 无 `converged` 字段，R 的 `gamlss()` 有 `$converged`。
2. 收敛只以 `additional_slots["rs_converged"]` 散落，四条路由口径不一
   （RS / CG v2 / CG 内联 full-hessian / JAX-RS / MIXED）。
3. 三个消费者静默误报：
   - `model_selection.compare_distributions` 读 `slots["converged"]`，RS 路径只写
     `rs_converged` → 该列**恒为 False**（与真实收敛相反）。
   - `api/grpc/server.py` 回退链默认值为 `True` → 未知时谎称收敛，gRPC 客户端会信。
   - MIXED metrics/verbose 四处直读 slot。
4. `serialization` 不落盘收敛状态。

**修复**：
- `GAMLSSModel` 新增一等字段 `converged: bool | None` + `termination_reason: str | None`
  + 统一访问器 `convergence_status()`（一等字段优先 → slot 回退 → None）。
  **一等字段优先 + slot 回退**的组合是刻意设计：既让新路径权威，又不破旧调用方/旧工件。
- 全路由 fail-closed 分类，词汇表：
  `relative_deviance_converged` / `max_iterations_reached` / `non_finite_deviance`
  (RS+JAX-RS)；`step_rejected` / `no_progress_step_rejected` (CG)；
  `cg_stage_not_converged` (MIXED 补位未收敛)。NaN/inf deviance 一律不收敛。
- gRPC fail-open(`True`) → fail-closed(`None` → `False`)；序列化 meta 往返 + legacy 读出 `None`。

**C6 状态澄清**（重要，避免重复劳动）：JAX 侧 NaN-as-convergence 已在 `2dcab9a` 修复
（`test_jax_rs_nan_handling.py` 覆盖）。本次修的是 NumPy RS 路径 + 模型容器 + 消费者，
即 C6 当时未覆盖的另一半。

**测试**：`tests/test_model_convergence_reporting.py`（11 项）。发散数据集必须
**精确复现历史探针的 rng 抽取顺序**（pareto→weibull→gumbel, seed 0）才能让 `g_dev` 真是
`inf` 而非有限大数 —— 自造"看起来该发散"的数据做不到这一点。

**方法论沉淀**：`git stash` 是隔离"既有失败 vs 本次引入"的最快手段。
本轮 3 类既有失败（`test_jax_rs_batch.py` ×3、`test_grpc_server.py::test_grpc_batch_fit_service_direct`、
`test_model_selection.py`）全部经它确认，**未修**（记录在案）。
另：pytest 摘要行会被 warning 淹没，回归用 `-p no:warnings --no-header` + `tail`。

**工件纪律**：`test_suite_sha256` 内嵌于 JSON 工件 → 任何 `tests/` 变更必须**同一 commit 内**
再生工件（`generate_coverage_artifacts.py` + `generate_capability_matrix.py` +
`coverage_diff_report.py --update-baseline`）。本轮已踩坑两次。

**新发现（R parity 缺口，候选下一项）**：Python 缺族级响应域校验。
R 的 GA 对含负响应直接 `stop("response variable out of range")`，本项目仅告警继续拟合。
既是 parity 缺口，也是伪收敛的潜在来源。

## D2.3 批量路径修复（commit e3a6ebe）

`batch_jax_rs_fit` **完全不可用**：JaxRSResult 加了 `eta_clip_ratio` 字段后，
vmap 路径的构造点没跟上 → `TypeError: missing 1 required positional argument`。
不是结果偏差，是每次调用直接崩。

**实测纠正了我的假设**：`eta_clip_ratio` 由**残差趋零**驱动，不是斜率过大。
NO 的 sigma 是 log link、`eta_bounds=(-6,6)`，无噪数据把 `exp(eta)` 压向下界：
- noiseless → 0.5000
- sd=0.4 → 0.0000
- sd=3.0 → 0.0000

我最初按"大斜率触发"写测试被实测打回。

**结构性风险（已登记未消除）**：`jax_rs_batch` 的 vmap kernel 是
`jax_rs_core` IRLS 的**独立重写**（vmap 不能直接调 core），逐段对应。
本次缺陷正是这种重复的后果。考虑过抽公共函数，但两处一处用 Python float
标量、一处用 traced 数组，抽取要在两种语义间妥协 → 改为**扩展 parity 断言
到全部 7 个字段**来锁漂移，比抽函数更贴合实际风险。

## D2.4 族级响应域校验（commit 693991b）

**事实纠正**：`stop("response variable out of range")` **不只在绘图函数**。
真正入口在 `gamlss/R/gamlss-5.R:960`（`gamlss()` 体内、任何 IRLS 步之前）。
且 **`gamlssML` 不做该校验** → Python `gamlss_ml` 保持宽松是正确的 parity
边界，不是漏接。

**最重要的一条方法论**：`_RESPONSE_DOMAINS` 初版我按"分布常识"给 19 个族
加了响应域限制（PO/ZINB/ALPHA/BETA/DAGUM/...）。核对 R 源码后发现
**这些族根本没有 `y.valid`**。凭空加限制会拒绝 R 正常拟合的数据 ——
**假拒绝比漏检更糟**。已全部移除，并把这条 provenance 规则写进模块注释。

教训：**"R 没说"不等于"R 默认放行"，也不能靠常识补**。族规则只能逐条
从 R 源码抄。

**parity 验证方式**：活 R bridge 确认 R 对 GA+负响应确实抛
`response variable out of range`（bridge 把 `stop` 包成 `RuntimeError`，
断言落在消息上而非 `{"success": False}` dict —— 这是实际行为，不是我一开始
假设的）。反向也测了正响应数据两侧 deviance rtol 1e-3 一致，证明没过度拒绝。

**接入位置**：`gamlss()` 内 `resolve_family` 之后、**所有方法路由之前**。
只护 NumPy RS 会让 CG/MIXED/RS_JAX 继续拟合 R 拒绝的数据。

**测试耗时坑**：`test_consistency_families.py`（45 项）跑 9 分钟才完，
前台 2 分钟超时会被打成 SIGTERM（看起来像失败，其实是超时）。
JAX 编译密集的批次要 `run_in_background`。另：沙箱会吞掉
`--collect-only` 和重定向的输出，看到"0 cases"或空输出别当结论。
