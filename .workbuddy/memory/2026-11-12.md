## D2.223 / P0-4：全库 8 分片发布门禁（发布门禁收尾之二）

- **现状**：`ci.yml` 已有 lint（black/ruff/mypy）+ 分层 collection gate；但
  `release.yml` 的 `pre-release-gate` 仍是**单进程全库** `python -m pytest tests/ -q` ——
  正是 MEMORY.md 记录会挂的方式（极慢 R bridge/重拟合文件整片 1h+、无独立 DB）。
- **交付**：
  1. 新增 committed 工具 `tools/pytest_shards.py`（替代 gitignored 的 `tmp/mk_shards.py`）：
     确定性排序 549 个 `test_*.py` → round-robin 8 分片（`files[i::8]`，把极慢文件摊开），
     repo 相对 POSIX 路径，`--check` 校验并集无损/无重复/无空片，产出 `fingerprint` 稳定摘要。
     本机实测 8 片 68–69 文件、无遗漏、`pytest @argfile` 从仓库根路径解析 OK。
  2. `release.yml`：`pre-release-gate` 去掉单进程全库，改为静态门禁组
     （`git diff --check` / 分层 collection `--strict-skips` / 分片自检 / ruff+black+mypy /
     required-R fail-closed）；新增 `sharded-suite` **8 分片 matrix job**，每片独立
     `OMNILSS_MODEL_DB_PATH`（避开 D2.216 的 sqlite 写锁）、`tee` 实时落盘 + `set -o pipefail` +
     上传分片日志；新增 `benchmark-recheck` **单进程**跑性能基准（MEMORY.md：0.5s 阈值是
     机器负载计时器，满载并发会 flaky，必须单独低负载复核）；`publish-pypi` 的 `needs` 接住
     build / test-install / pre-release-gate / sharded-suite / benchmark-recheck 全部。
  3. 新增 `omnilss/tests/test_release_sharding.py`（10 例）：分片工具确定性/无损/均衡/边界/
     CLI `--check`，以及 workflow 文本级断言（8 分片 matrix、独立 DB、tee、静态门禁、
     非单进程、publish 被全门禁 gate）。用文本断言而非 pyyaml，避免验收测试因缺依赖被 skip。
